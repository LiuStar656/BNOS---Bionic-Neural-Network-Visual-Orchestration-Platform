# 01 复合节点虚线修复与端口别名规范化

## 问题现象

独立节点连接复合节点时，线条先显示蓝色实线，然后立刻变成**红色/灰色虚线**（无效边渲染态）。日志中可以看到画布上的 EdgeKey 与 CanonicalEdgeSet 不匹配。

## 根因 1 — composite.json 读取路径拼接错误

Canonical Edge Resolver 反向推导复合节点权威边集合时，路径多拼了一层 `NODE_DIR_ROOT`：

```python
# ❌ 旧代码：拼接后变成 project/nodes/composite_nodes/<id>/composite.json
comp_path = project_path / NODE_DIR_ROOT / COMPOSITE_DIR_NAME / cid
```

实际 composite.json 在 `project/composite_nodes/<id>/composite.json`（`nodes/` 和 `composite_nodes/` 是并列目录，不是嵌套关系），导致：
- 每次都读不到 composite.json
- `COMPOSITE_INPUT` / `COMPOSITE_OUTPUT` / `COMPOSITE_INTERNAL` 3 类权威边**全部为 0**
- 画布上所有涉及复合节点的连线都被判成「幽灵边」→ 虚线渲染

### 修复

```python
# ✅ 新代码：去掉 NODE_DIR_ROOT
comp_path = project_path / COMPOSITE_DIR_NAME / cid
```

## 根因 2 — 端口别名 mismatch（画布 default ↔ 权威 data）

连线时画布锚点名是 UI 显示名 `default`，而 composite.json 内部路由键用的是 `data`（这是两套命名体系遗留的别名）：
- 画布 EdgeKey：`(COMPOSITE_INPUT, upstream_id, comp_id, 'upstream_out', 'default')`
- 权威 EdgeKey：`(COMPOSITE_INPUT, upstream_id, comp_id, 'upstream_out', 'data')`

5 元组不相等 → 不匹配 → 渲染虚线。

输出端口也存在同样问题：外部 `default` ↔ 内部 `node_output` 是同一个端口的别名。

### 修复 A — 权威集生成端做别名扩展（canonical_edge_resolver.py）

解析 composite.json 的 `external_connections.input/output` 时，遇到兼容端口名对就**同时把 EdgeKey 的两个版本都放进权威集**：
- 输入端口别名对：`{data, default}`
- 输出端口别名对：`{node_output, default}`

这样无论画布上用的是哪一端口径，都能在权威集中命中。

### 修复 B — 静态校验端做别名比较（node_state_manager.py `is_edge_valid_static`）

EdgeKey 比较时增加「别名端口等价」分支：
```
same_port(a, b) ↔ a == b
                 OR (a,b ∈ {data, default})
                 OR (a,b ∈ {node_output, default})
```
兼容历史画布布局里的旧口径。

### 修复 C — 路由写入端统一规范化（composite_node.py set_input_routing / set_output_routing）

两个历史写入路径口径不一致导致 composite.json 同时存在 `data` 和 `default` 两个**指向同一个上游**的重复条目：
- `canvas_connections.create_edge` → 传入内部标准名 `data`
- `composite_node._sync_configs_for_collapse`（从子节点 input_ports 反向推导）→ 直接传 UI 锚点名 `default`

在 `set_input_routing` 和 `set_output_routing` **入口处强制规范化**：

```python
# 输入：default 与 data 等价，统一用 data
raw_port = (port_name or "").strip() or "default"
norm_port = "data" if raw_port in {"data", "default"} else raw_port

# 输出：default 与 node_output 等价，统一用 node_output
norm_port = "node_output" if raw_port in {"node_output", "default"} else raw_port
```

写入后**再反删另一个别名键**（防止历史脏数据残留）：
```python
if raw_port != norm_port and raw_port in routing["input"]:
    del routing["input"][raw_port]
```

### 修复 D — 路由清理端别名宽松匹配（clear_input_routing / clear_output_routing）

调用方可能传入任一端口别名，清理时不能只比对单键名：
- `clear_input_routing(port)` → 先删标准名命中，再删别名键（`data` ↔ `default`）
- `clear_output_routing(port)` → 先删标准名命中，再删别名键（`node_output` ↔ `default`）

`node_clusters.json` 全局同步里清理跨复合节点引用时，也按别名宽松口径比对。

## 验证点

1. 独立节点 → 复合节点输入锚点连线后，**30 秒以上持续保持蓝色实线**（不会 3 秒后变虚线）
2. `composite.json external_connections.input_ports` 写入后**只含 `['data']`**，不再出现 `['data','default']` 双头重复
3. 读取历史布局（画布上保存的是 `default` 口径）也能正确匹配，不渲染虚线
4. `canvas_connections._remove_redundant_composite_edges` 去重数量不会再出现重复边

## 修改文件

| 文件 | 改动 |
|------|------|
| `ui/core/edge/canonical_edge_resolver.py` | 去掉路径拼接里冗余的 `NODE_DIR_ROOT`；复合边加入端口别名扩展（data↔default / node_output↔default 两种 EdgeKey 都入权威集） |
| `ui/core/state/node_state_manager.py` | `is_edge_valid_static` 增加复合边别名端口等价比较，兼容画布上的旧口径 |
| `ui/canvas/mixins/canvas_connections.py` | `create_edge` 创建复合节点边时统一使用内部端口名（data / node_output），减少后续转换负担 |
| `ui/core/node/composite_node.py` | `set_input_routing` / `set_output_routing` 入口统一规范化到标准名 + 清理别名脏键；`clear_input_routing` / `clear_output_routing` 别名宽松匹配 |
