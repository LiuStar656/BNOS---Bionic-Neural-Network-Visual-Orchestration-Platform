# 自定义标题栏窗口缩放修复

## 问题描述

引入自定义标题栏（`DarkTitleBar` + `FramelessWindowHint`）后，主窗口无法通过拖拽边缘调整尺寸。

## 根因分析

经过 5 轮迭代排查，最终定位到两个独立根因：

### 一、`nativeEvent` 被 Python MRO 遮蔽

`BNOSMainWindow` 的多继承定义为：

```python
class BNOSMainWindow(QMainWindow, ..., MainWindowInteractionMixin):
```

Python MRO 中 `QMainWindow` 排在所有 Mixin 之前。当 Qt 调用 `nativeEvent` 时，Python 首先在 `QMainWindow` 中找到该方法，`MainWindowInteractionMixin.nativeEvent` **永远不会被调用**。因此拦截 `WM_NCHITTEST` 的逻辑从未生效。

### 二、`ctypes.MSG` 结构体内存对齐导致坐标提取错误

前几轮尝试通过 `ctypes.Structure` 解析 Windows `MSG` 结构体，从 `lParam` 中提取光标坐标：

```python
msg = MSG.from_address(int(message))
x = msg.lParam & 0xFFFF
y = (msg.lParam >> 16) & 0xFFFF
```

64 位 Windows 下 `MSG` 结构体内部存在隐式对齐填充（`message` 4 字节后补 4 字节对齐 `wParam`），`ctypes` 默认对齐策略与实际内存布局不一致，导致读出的 `lParam` 值是错位的。

症状表现为：上边缘无法调整、左边缘不识别、右/右下判定范围偏移。

## 修复方案

### 1. `nativeEvent` 直接写在主类

将 `nativeEvent` 从 `interaction.py` Mixin 移除，直接定义在 `BNOSMainWindow.__main__.py` 主类中。

```python
class BNOSMainWindow(QMainWindow, ...):
    def nativeEvent(self, eventType, message):
        ...
```

### 2. 使用 `QCursor.pos()` 替代 MSG.lParam

放弃 `ctypes` 解析 `MSG` 结构体获取坐标，改用 Qt 高层 API：

```python
from PySide6.QtGui import QCursor
cursor_pos = QCursor.pos()
x, y = cursor_pos.x(), cursor_pos.y()
```

仅保留 `MSG_HEADER`（`hwnd` + `message` 两个字段）用于判断消息类型，这两个字段偏移小、不受对齐影响。

### 3. 移除失败的 Win32 hack

删除 `_enable_native_resize()` 方法——该方法尝试通过 `SetWindowLongW` 给 `WS_POPUP` 注入 `WS_THICKFRAME`，对纯 `WS_POPUP` 窗口无效，且引入了顶部边框视觉不一致问题。

之前还尝试过 `DwmExtendFrameIntoClientArea`，同样导致 resize 彻底失效。

## 修改文件

| 文件 | 修改内容 |
|------|----------|
| `ui/main_window/__main__.py` | 新增 `nativeEvent` 方法（`WM_NCHITTEST` + `QCursor.pos()`）；删除 `_enable_native_resize()` |
| `ui/main_window/interaction.py` | 删除 Mixin 中的死代码 `nativeEvent`，添加注释说明 MRO 遮蔽原因 |
