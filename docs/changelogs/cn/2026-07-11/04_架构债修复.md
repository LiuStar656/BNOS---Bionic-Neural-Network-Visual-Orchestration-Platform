# 架构债修复

## 更新概述

针对软件架构层面存在的技术债进行系统修复，包括消除双选状态、修复懒导入、消除不可靠的析构函数、修复节点扫描逻辑与进程清理问题。

## 核心改动

### 1. P0-1：消除双选状态 (Eliminate Dual Selection State)

**问题**：`box_selected_nodes`（Python list）和 `QGraphicsItem.isSelected()`（Qt C++）是两个独立的状态源，每次选择操作需手动同步两个列表，已导致 Ctrl+双击 toggle bug。

**方案**：不消除 `box_selected_nodes`属性，而是将其从独立状态存储变为 **Qt 选择的投影** —— 通过代理类 `SelectedNodesList` 将所有读写委托给 `QGraphicsScene.selectedItems()`。

修改 `ui/canvas/canvas_view.py`：

- **新增 `SelectedNodesList` 代理类**（65行）：实现 `__iter__` / `__len__` / `__contains__` / `__getitem__` / `__bool__` / `append` / `remove` / `clear` 全部委托给 `scene.selectedItems()`，保持与原 list 接口完全兼容
- `self.box_selected_nodes = []` → `SelectedNodesList(self)`
- `CompositeNodeItem` / `CompositeNode` 懒导入提升为模块级导入

修改 `ui/canvas/mixins/canvas_selection.py`：

- `on_node_selected()`：用 `scene.clearSelection()` + `node.setSelected(True)` 替代手动操作列表
- `_toggle_node_selection()`：基于 `node.isSelected()` 判断替代 `node_name in box_selected_nodes`
- `clear_selection()`：调用 `scene.clearSelection()`

修改 `ui/canvas/mixins/canvas_box_select.py`：

- `self.canvas.box_selected_nodes = []` → `.clear()`（此处直接赋值会替换掉代理对象，造成严重 bug）

修改 `ui/canvas/mixins/canvas_event_handlers.py`：

- 框选逻辑：用 `scene.clearSelection()` + `setSelected(True/False)` 替代手动 `.append()` 循环

修改 `ui/canvas/mixins/canvas_batch_ops.py`：

- `self.canvas.selection.box_selected_nodes` → `self.canvas.box_selected_nodes`（修正路径）

### 2. P1-1：修复 CompositeNode 懒导入

**问题**：多个文件中 `CompositeNode` 在方法体内懒导入，存在重复导入和不必要的运行时开销。

修改 `ui/panels/node_list_context.py`：

- 删除 `_ensure_composite_manager()` 内重复的 `from ui.core.composite_node import CompositeNode`（已模块级导入）

修改 `ui/canvas/canvas_view.py`：

- `restore_composites()` 内 `CompositeNodeItem` / `CompositeNode` 提升为模块级导入

### 3. P1-2：消除 `__del__` 进程清理

**问题**：`TerminalProcess.__del__` 依赖 Python GC 的不确定性析构来终止子进程，在 Qt 环境下不可靠。Python GC 运行时 C++ 对象可能已被销毁。

修改 `ui/core/terminal/terminal_process.py`：

- `__del__` → `dispose()` 显式清理方法，调用 `stop()` + `deleteLater()`
- 调用方在 `TerminalWidget.close_terminal()` 中显式调用 `dispose()`

修改 `ui/core/terminal/terminal_widget.py`：

- `close_terminal()` 从 `self.process.stop()` 改为 `self.process.dispose()`

### 4. Bug 修复：无 config.json 的目录被当作节点加载

**问题**：`nodes/` 目录下没有 `config.json` 的文件夹也被当作节点加载到节点列表。未来 `nodes/` 中放入其他用途的子文件夹也会被误识别为节点。

**根因**：两处节点扫描逻辑（`project_load_worker.py` 和 `core_process.py`）都只过滤非目录项，不检查 `config.json` 是否存在。缺失时要么用合成默认配置（GUI），要么用空 config（headless），都不拒绝。

修改 `ui/core/project_load_worker.py`：

- `is_dir` 检查后增加 `config.json` 存在性检查，不存在则 `continue` 跳过
- 删除合成默认配置分支（无 config.json 不再伪造配置）

修改 `ui/core/core_process.py`：

- `is_dir` 检查后增加 `config.json` 存在性检查，不存在则 `continue` 跳过
- config.json 解析失败也 `continue` 跳过

### 5. Bug 修复：QProcess Destroyed while running

**问题**：关闭应用时终端控件的 `closeEvent` 在父控件级联销毁场景下可能被跳过，导致 `QProcess` 在 powershell.exe 还在运行时被销毁，Qt 报出警告。

**根因**：`closeEvent()` 只在控件通过用户操作关闭时触发，整体窗口关闭时的子控件级联销毁不保证调用。

修改 `ui/core/terminal/terminal_widget.py`：

- `__init__` 中增加 `self.destroyed.connect(self.close_terminal)`，利用 Qt 的 `destroyed` 信号（在 QObject 析构时同步触发）作为兜底保障
- `_is_closing` 守卫防止重复清理
