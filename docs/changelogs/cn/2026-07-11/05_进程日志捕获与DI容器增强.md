# 进程日志捕获与 DI 容器增强

## 更新概述

针对代码评审中指出的调试友好性不足和 DI 容器过于简单两个问题进行专项改进。子进程输出从丢弃改为持久化日志文件，DI 容器增加命名注册、作用域控制和服务查询能力，同时保持完全向后兼容。

## 核心改动

### 1. 子进程 stdout/stderr 日志文件捕获

**问题**：节点子进程的 `stdout` / `stderr` 直接丢弃到 `subprocess.DEVNULL`。当节点启动失败时，没有任何日志可供排查原因，只能看到 `exit=1` 这样的误差信息。

**方案**：将输出重定向到节点目录下的日志文件，启动失败时自动读取日志尾部并包含在错误消息中。

修改 `ui/core/node_process.py`：

- **新增 `_rotate_log()`**：日志文件超过 5MB 时自动截断保留尾部，防止磁盘无限增长
- **新增 `_open_node_logs()`**：启动时为节点创建 `node_output.log` 和 `node_error.log`，写入时间戳标记头
- **新增 `_read_tail()`**：读取日志文件尾部 N 行（默认 50 行），编码容错
- **修改 `start_node_process()`**：
  - 移除 4 处 `subprocess.DEVNULL`，全部替换为日志文件句柄
  - 启动失败路径不再调用无意义的 `process.communicate()`，改为读取日志文件尾部内容
  - 启动成功路径在 `Popen` 后立即关闭父进程日志句柄（子进程有独立句柄副本，不受影响）
  - 异常路径兜底关闭日志句柄
- **新增公开 API `get_node_log_tail(node_path)`**：UI 面板可随时调用，获取运行中节点的实时 stdout/stderr 尾部

### 2. DI 容器增强

**问题**：`DIContainer` 内部是 `Dict[Type, Any]`，以类类型作为 key。这意味着：(a) 同一接口无法注册多个实现；(b) 无法用字符串名称代替类型注册（如第三方库接口）；(c) 工厂方法总是被视为单例；(d) 解析失败时只报类型名，不提示已注册了哪些服务。

**方案**：重构内部存储为复合键 `(interface, name)`，新增 `register()` / `resolve_named()` / `list_registered()` 方法，保持旧 API 签名和语义完全不变。

修改 `ui/core/di.py`：

- **内部 `_Key` 复合键**：`(interface_type, name)`，其中 `name` 为 `None` 时等价于旧 API 的无名注册
- **统一注册 `register(interface, instance_or_factory, *, name, scope)`**：
  - 支持命名注册 `name="file"` — 同一接口可注册多个实现
  - 支持作用域 `scope="transient"` — 每次 `resolve()` 调用工厂新建实例
  - 默认 `scope="singleton"` — 单例缓存，与旧行为一致
  - `instance_or_factory` 智能判断：可调用非类对象视为工厂函数
- **`resolve()` 增强**：
  - `resolve(str)` — 按名称全局查找
  - `resolve(Type, name=...)` — 按类型 + 名称限定
  - `resolve(Type)` — 向后兼容，等同于 `resolve(Type, name=None)`
- **`is_registered()` 增强**：支持 `is_registered("name")` 字符串查询
- **`resolve_named(name)`**：按名称解析的便捷方法
- **`list_registered()`**：列出所有已注册服务 `[(type, name, scope), ...]`
- **`_not_found_msg()` 增强**：解析失败时自动列出所有已注册服务（含名称和作用域），大幅提升调试效率
- **旧 API 完全兼容**：`register_instance()` / `register_factory()` / `resolve()` / `is_registered()` 签名和语义不变

## 测试更新

修改 `tests/test_di_container.py`：

- 保留全部 6 个原有测试（`TestDIContainerBackwardCompat` 类）
- 新增 12 个测试，覆盖：
  - 命名注册与按名称解析
  - 同一接口多实现
  - transient 作用域（每次新建）
  - singleton 作用域（单例缓存）
  - 无效 scope 参数拒止
  - `is_registered()` 字符串查询
  - `list_registered()` 服务列表
  - 未注册时的错误信息包含已注册服务列表
