# 启动队列僵尸条目修复

## 问题描述

复合节点停止后无法再次启动，点击启动显示"加入队列失败"。

## 根本原因

`NodeStartupQueueManager._on_node_start_complete` 在节点启动成功后设置 `item.status = QueueStatus.SUCCESS`，但**从未从 `self._queue` 列表中移除该项**。

用户再次点击启动时，`enqueue()` 检查 `node_name in [item.node_name for item in self._queue]` 发现了上次的 SUCCESS 条目，直接返回 `False`，导致启动被拒绝。

## 修复方案

### 1. 清理终态条目

在 `_on_node_start_complete` 中，当项到达终态时调用 `_remove_from_queue()`：

```python
def _on_node_start_complete(self, item, success, error):
    if success:
        item.status = QueueStatus.SUCCESS
        self._remove_from_queue(item)  # ← 新增
        ...
    else:
        if item.retry_count < self._max_retry:
            item.status = QueueStatus.QUEUED  # 重试，不移除
        else:
            item.status = QueueStatus.FAILED
            self._remove_from_queue(item)  # ← 新增
```

### 2. 防御性加固 enqueue

`enqueue` 的重复检查只考虑非终态项：

```python
def enqueue(self, node_name, ...):
    active_names = {
        item.node_name
        for item in self._queue
        if item.status not in (SUCCESS, FAILED, CANCELLED)
    }
    if node_name in active_names:
        return False  # 真正活跃的重复 → 拒绝
    # 终态条目即使残留也不影响重新入队
```

## 改进效果

- 复合节点停止后可以正常再次启动
- 启动队列不会无限增长（SUCCESS/FAILED 条目自动清理）
- 防御性设计确保即使清理漏掉也不阻塞
