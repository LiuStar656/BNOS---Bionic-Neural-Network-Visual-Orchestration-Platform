# 03 复合节点展开坐标与连线修复

## 问题描述

展开复合节点后出现两个问题：
1. **子节点位置偏移**：展开后的子节点跑到其他地方，不在复合节点原来的位置
2. **连线丢失**：外部节点与复合节点的连线末端留在原地，没有正确连接到展开后的子节点

## 根因分析

### 问题 1：坐标偏移

展开时使用了保存的旧 `canvas_position`，而不是复合节点当前的实际位置。当复合节点被移动后再展开，子节点会被定位到旧位置。

**修复前代码**：
```python
comp_pos = comp.get("canvas_position", {"x": 0, "y": 0})
```

**修复后代码**：
```python
comp_pos = {
    "x": comp_item.pos().x(),
    "y": comp_item.pos().y(),
}
```

### 问题 2：连线映射失败

复合节点的默认输入锚点名称是 `"default"`，但 `_identify_ports` 中主输入端口名称是 `"data"`，导致 `_morph_composite_to_internal_edges` 无法找到对应的内部节点。

**修复方案**：添加 `"data"` → `"default"` 的端口名称映射。

### 问题 3：布局加载恢复旧坐标

`canvas_layout.json` 保存了所有节点的坐标，包括复合节点的内部子节点。当加载布局时，子节点的位置被恢复到旧位置，与复合节点的位置不一致。

**修复方案**：保存和加载布局时跳过折叠复合节点的子节点。

## 修复内容

### 3.1 展开坐标修复

**文件**：`ui/core/node/composite_node.py`

展开时直接从 `comp_item.pos()` 获取当前位置，而不是使用保存的 `canvas_position`。

### 3.2 端口名称映射

**文件**：`ui/core/node/composite_node.py`

在 `_morph_composite_to_internal_edges` 中添加 `"data"` → `"default"` 的端口名称映射，确保默认输入锚点能正确找到内部节点。

### 3.3 布局保存/加载过滤

**文件**：`ui/canvas/mixins/canvas_layout.py`

- 保存布局时：跳过折叠复合节点的子节点，只保存复合节点坐标
- 加载布局时：跳过折叠复合节点的子节点，不会恢复旧位置

### 3.4 执行顺序调整

**文件**：`ui/core/node/composite_node.py`

将 `_morph_composite_to_internal_edges` 移到子节点定位之后执行，确保新创建的边端点使用正确的子节点位置。

## 修改文件清单

| 文件 | 改动 |
|------|------|
| `ui/core/node/composite_node.py` | 展开时使用当前位置；添加端口名称映射；调整执行顺序 |
| `ui/canvas/mixins/canvas_layout.py` | 保存/加载布局时跳过折叠复合节点的子节点 |

## 效果验证

修复后：
- ✅ 展开复合节点时，子节点正确定位到复合节点当前位置
- ✅ 外部节点与复合节点的连线正确连接到展开后的子节点
- ✅ 折叠后移动复合节点，再次展开子节点位置正确
- ✅ 保存/加载布局后，复合节点展开位置正确
