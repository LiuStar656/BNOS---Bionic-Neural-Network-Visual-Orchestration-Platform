# 状态机系统

## 问题描述

项目中多个模块存在隐式的状态管理逻辑，使用裸字符串比较和散落的 bool 标志，导致：
- 状态转换无校验（如重复启动、非法停止）
- TOCTOU 竞态条件（检查与操作之间状态可能变化）
- 资源泄漏（异常路径未清理）
- 状态值不统一（3 套矛盾的状态字符串并存）

## 方案设计

在 `ui/core/state/` 下创建独立状态机包，零业务依赖，基于 `QObject` + `Signal` 架构。

### 状态机基类 (`base.py`)

```python
class StateMachine(QObject):
    """通用有限状态机，基于 QObject + Signal。"""
    state_changed = Signal(str, str)  # (old_state, new_state)

    def handle(event: str) -> bool    # 触发事件，返回是否成功
    def can(event: str) -> bool       # 只读检查（不执行转换）
    def reset() -> None               # 重置到初始态
    def get_allowed_events() -> list  # 获取当前允许的事件
```

`Transition` 数据类：`event` / `source` / `target` / `guard` / `action`，支持 `"*"` 通配符。

### Phase 1: NodeRuntimeSM — 节点运行时状态机

文件: `ui/core/state/node_runtime.py`

```
STOPPED → STARTING → RUNNING ⇄ IDLE
                            ↓ crash
                         CRASHED
STARTING → CRASHED (timeout)
RUNNING → STOPPING → STOPPED
STOPPING → CRASHED (kill failed)
CRASHED → STARTING (retry)
```

- 6 个状态 (`NodeRuntimeState` str Enum)
- 14 条转换规则
- 统一 `node_process.py` / `node_control_service.py` / `node_startup_queue.py` 中 3 套矛盾的状态值

### Phase 2: CompositeLifecycleSM — 复合节点生命周期状态机

文件: `ui/core/state/composite_lifecycle.py`

```
CREATED → STARTING → RUNNING → STOPPING → STOPPED → STARTING (restart)
                ↓ timeout/err    ↓ crash     ↓ kill_fail
             CRASHED ←───────────────────────┘
CREATED/STOPPED/CRASHED → REMOVING → REMOVED (decompress)
```

- 8 个状态
- 15 条转换规则
- Properties: `is_active`, `is_terminal`, `is_restartable`

### Phase 3: CanvasModeSM — 画布交互模式状态机

文件: `ui/core/state/canvas_mode.py`

```
NORMAL ⇄ CONNECTING
NORMAL ⇄ PANNING
NORMAL ⇄ BOX_SELECTING
NORMAL ⇄ SINGLE_SELECT
```

- 6 种模式 (`CanvasMode` str Enum)
- 14 条转换规则
- 排除规则: CONNECTING 阻塞 PANNING；BOX_SELECTING 阻塞 CONNECTING

### Phase 4: EdgeInteractionSM — 边交互状态机

文件: `ui/core/state/edge_interaction.py`

```
IDLE → HOVERING_HANDLE → HOLDING_HANDLE → DRAGGING_NEW_WP
IDLE → HOVERING_WP → DRAGGING_WP
```

- 6 个状态
- 8 条转换规则
- `is_interacting` 属性区分交互态与空闲态
