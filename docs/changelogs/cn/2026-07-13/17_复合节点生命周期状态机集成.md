# 复合节点生命周期状态机集成

## 问题描述

复合节点管理系统存在以下状态管理问题：
- 重复启动无保护（TOCTOU 竞态）
- 异常路径资源泄漏（日志文件句柄未关闭）
- 停止操作无反馈（不知道 kill 是否成功）
- `is_running` 检查依赖内存中的 Popen 对象（不持久化）

## 修复方案

将 `CompositeLifecycleSM` 集成到 `composite_node.py` 的 5 个关键方法中。

### `_get_lifecycle(comp_id)`

获取或创建复合节点生命周期状态机，存储在 `self._lifecycle` 字典中。

### `start_inprocess`

```python
lc = self._get_lifecycle(comp_id)
# TOCTOU 防护：状态机 is_restartable 替代裸 dict 检查
if not lc.is_restartable:
    return False, "already running"
lc.handle("start")  # → STARTING

# ... 启动编排器进程 ...

lc.handle("start_ok")    # → RUNNING (成功)
lc.handle("start_timeout")  # → CRASHED (进程立即退出)
lc.handle("start_fail")     # → CRASHED (异常)
```

**资源泄漏修复**：异常路径补全 `_composite_log_files` 清理：
```python
log_files = self._composite_log_files.pop(comp_id, (None, None))
for fh in log_files:
    if fh is not None:
        try: fh.close()
        except OSError: pass
```

### `stop_composite`

```python
lc = self._get_lifecycle(comp_id)
# 状态机守卫：只在活跃状态时允许停止
if not lc.is_active:
    return False, "not running"
lc.handle("stop")  # → STOPPING

# ... 终止进程树 ...

lc.handle("stop_ok")   # → STOPPED (成功)
lc.handle("stop_fail")  # → CRASHED (兜底清理失败)
```

### `decompress`

```python
lc = self._get_lifecycle(comp_id)
lc.handle("decompress")     # → REMOVING
# ... 解压缩清理 ...
lc.handle("remove_done")    # → REMOVED
# 清理生命周期状态机
self._lifecycle.pop(comp_id, None)
```

### `is_running`

委托生命周期状态机：
```python
def is_running(self, comp_id):
    lc = self._lifecycle.get(comp_id)
    if lc is not None:
        return lc.is_active  # STARTING / RUNNING / STOPPING
    # 兜底：状态机未初始化时回退到 Popen 检查
    proc = self._active_processes.get(f"__composite_{comp_id}")
    return proc is not None and proc.poll() is None
```

## 改进效果

- TOCTOU 竞态消除：`is_restartable` 一次检查覆盖 CREATED/STOPPED/CRASHED 三种可重启状态
- 资源泄漏修复：异常路径完整关闭日志文件句柄
- 停止反馈：`stop_ok` / `stop_fail` 明确区分成功与失败
- 状态一致性：`is_running` 从状态机读取（CREATED→正在压缩阶段→不算 running）
