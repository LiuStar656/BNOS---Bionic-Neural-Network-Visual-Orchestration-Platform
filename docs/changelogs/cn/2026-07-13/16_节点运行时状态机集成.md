# 节点运行时状态机集成

## 问题描述

`node_process.py` 中直接操作 `node_info["status"]` 裸字符串，无状态转换校验，存在：
- 运行中节点可能被重复启动
- 已停止节点无法正确识别（状态不一致）
- `check_running_processes` 轮询直接赋值状态，绕过了状态机

## 修复方案

### 桥接层 (`node_runtime_bridge.py`)

创建轻量兼容层，不影响现有 `node_info["status"]` 字典读写：

```python
def ensure_sm(node_info) -> NodeRuntimeSM   # 获取或创建 SM
def get_state(node_info) -> str              # 从 SM 读取状态（含 fallback）
def transition_state(node_info, event) -> bool  # 触发转换 + 同步 dict
def sync_status_to_dict(node_info) -> None   # 同步 SM → dict
```

### node_process.py 集成

**`start_node_process`**
- 开头: `transition_state(node_info, "start")` — STOPPED/CRASHED → STARTING，非法状态直接拒绝
- 成功: `transition_state(node_info, "start_ok")` — STARTING → RUNNING
- 失败: `transition_state(node_info, "start_fail")` — STARTING → CRASHED（进程退出 / 异常）

**`stop_node_process`**
- 开头: `transition_state(node_info, "stop")` — RUNNING/IDLE → STOPPING，非法状态直接拒绝
- 成功: `transition_state(node_info, "stop_ok")` — STOPPING → STOPPED
- 失败: `transition_state(node_info, "stop_fail")` — STOPPING → CRASHED（兜底清理失败）

**`check_running_processes`**
- 进程存活 + 活跃子进程 → `child_resume`（IDLE → RUNNING）
- 进程存活 + 无活跃子进程 → `child_idle`（RUNNING → IDLE）
- 进程死亡 → `crash`（RUNNING/IDLE → CRASHED）
- 僵尸进程（SM 与实际不同步）→ 直接修正 dict + 重置 SM

**`detect_running_nodes`**
- `info.get("status")` → `get_state(info)` 统一读取

## 修改文件

| 文件 | 改动 |
|------|------|
| `ui/core/state/node_runtime_bridge.py` | 新增：桥接兼容层 (`ensure_sm` / `transition_state` / `get_state`) |
| `ui/core/node/node_process.py` | `start_node_process`: SM 启动守卫 + start/start_ok/start_fail 转换；`stop_node_process`: SM 停止守卫 + stop/stop_ok/stop_fail 转换；`check_running_processes`: child_resume/child_idle/crash 转换 + 僵尸处理；`detect_running_nodes`: 统一 get_state 读取 |
