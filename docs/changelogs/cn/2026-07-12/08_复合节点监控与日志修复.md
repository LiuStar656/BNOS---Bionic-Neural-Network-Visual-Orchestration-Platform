# 08 复合节点监控与日志修复

## 概述

修复复合节点在画布折叠状态下"监控黑洞"和"日志黑洞"两个问题。修复后折叠态复合节点可显示聚合 CPU/MEM 和运行状态，日志落盘可供查看。

---

## 一、问题诊断

| 问题 | 根因 | 影响 |
|------|------|------|
| **资源监控黑洞** | `CompositeNodeItem` 未集成 `NodeStatusWidget`，不订阅 `node_state_updated` 信号 | 折叠态看不到 CPU/内存，不知道是否在运行 |
| **日志黑洞** | `start_inprocess()` 的 `stdout/stderr=PIPE`，不写文件 | `node_output.log` / `node_error.log` 不存在，右键 View Log 为空 |

而复合节点的 **PID 已经有了**（`__composite_{id}.pid`），`psutil` 进程树采集也已有——只是没接上。

---

## 二、修改清单

| 文件 | 改动 | 行数 |
|------|------|:---:|
| `composite_node.py` | PIPE → 文件落盘 + `_composite_log_files` 字典 + `stop_composite` 关闭句柄 | +20 |
| `composite_node_item.py` | QTimer + psutil 进程树采集 + 折叠态 CPU/MEM/状态灯 | +85 |
| `system_resource_collector.py` | `get_node_pid()` 回退查找 `__composite_{id}.pid` | +14 |
| `node_list_ops.py` | `view_node_log` → 复合节点双日志路径 | +30 |

---

## 三、效果

```
折叠态复合节点（运行中）:
┌──────────────────────────────────┐
│ ◈ image_pipeline    ● running    │  ← 新增状态灯
│ 3 nodes · inprocess              │
│ CPU: 145%  MEM: 3.18 GB          │  ← 新增聚合 CPU/MEM
└──────────────────────────────────┘

右键 → View Log:
  composite_output.log    ← 编排器 stdout
  composite_error.log     ← 编排器 stderr（包含子节点异常）
```

关键设计：资源监控复用 `collect_process_resources(pid)` 的进程树遍历，一个 PID 自动聚合所有子节点进程。
