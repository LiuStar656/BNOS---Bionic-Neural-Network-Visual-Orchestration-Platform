# 复合节点独立目录结构方案

## 一、问题

当前复合节点的 5 类产物散落在 4 个不同位置：

| 产物 | 当前位置 | 依赖 |
|------|------|:---:|
| venv | `nodes/{display_name}_venv/` | 改名即裂 |
| orchestrator 脚本 | 项目根 `orchestrator_{comp_id}.py` | 无独立归属 |
| 配置文件 | `composite_nodes/{comp_id}/` | ✅ 已独立 |
| 日志 | `composite_nodes/{comp_id}/logs/` | ✅ 已独立 |
| 节点输出缓存 | `nodes/{name}/output.json` | 混在子节点中 |

清空一个复合节点需要操作 4 个不同目录，且 `display_name` 改名会导致 venv 路径失效。

---

## 二、目标目录结构

```
composite_nodes/<comp_id>/
├── composite.json           # 身份 + 端口 + 资源预算（已有）
├── node_registry.json       # 子节点运行时登记簿（已有）
├── pipeline.json            # 【新增】纯 DAG 拓扑（运行时读取）
├── orchestrator.py          # 编排脚本（从项目根迁入）
├── logs/                    # 日志（已有）
│   ├── composite_output.log
│   └── composite_error.log
├── output/                  # 【新增】各子节点输出缓存
│   ├── preprocess.output.json
│   └── inference.output.json
└── venv/                    # 【迁移】从 nodes/{name}_venv/ 迁入
    ├── Scripts/python.exe
    └── lib/
```

### 与独立节点完全隔离

```
项目根/
├── nodes/                   ← 独立节点（不动）
│   ├── preprocess/
│   │   ├── config.json
│   │   └── main.py
│   └── inference/
│       ├── config.json
│       └── main.py
├── composite_nodes/         ← 复合节点（完全隔离）
│   ├── composite_c0f0d436/  ← 一个目录 = 一个复合节点的全部
│   └── .archive/
└── node_clusters.json       ← 画布引用
```

## 三、关键设计

### 3.1 pipeline.json — 脱壳 DAG

从 `composite.json` 的 DAG 信息中提取最少执行信息：

```json
{
  "comp_id": "composite_c0f0d436",
  "generated_at": "2026-07-12T18:00:00",
  "nodes": [
    {
      "name": "preprocess",
      "path": "nodes/preprocess",
      "module": "nodes.preprocess.main"
    },
    {
      "name": "inference",
      "path": "nodes/inference",
      "module": "nodes.inference.main"
    }
  ],
  "edges": [
    {"from": "preprocess", "to": "inference"}
  ]
}
```

与 `composite.json` 的关系：
- `composite.json` = 身份 + 端口 + 资源预算 + 完整 nodes/edges（配置层）
- `pipeline.json` = 纯 DAG 拓扑（运行时层）
- `pipeline.json` 任何时候都可以从 `composite.json` 重新生成

### 3.2 orchestrator.py — 通用引擎

```python
# 编排器启动时读取 pipeline.json，不再硬编码 DAG
PIPELINE = json.load(open(Path(__file__).parent / "pipeline.json"))

class DagRunner:
    def __init__(self):
        for n in PIPELINE["nodes"]: ...
    
    def run(self, external_input=None):
        for node_name in self._topo_sort():  # 从 PIPELINE["edges"] 拓扑排序
            ...
```

DAG 变更时只需更新 `pipeline.json`，**不需要重新生成 orchestrator.py**。

### 3.3 独立的 output 缓存

```
composite_nodes/<comp_id>/output/
├── preprocess.output.json
└── inference.output.json
```

- 不再写入子节点 `nodes/{name}/output.json`
- 子节点的 output.json 保留给独立执行场景
- 断点续跑（checkpoint）也使用此目录

### 3.4 venv 迁移

| 阶段 | old path | new path |
|------|------|------|
| venv | `nodes/{display_name}_venv/` | `composite_nodes/{comp_id}/venv/` |
| Python | `nodes/{display_name}_venv/venv/Scripts/python.exe` | `composite_nodes/{comp_id}/venv/Scripts/python.exe` |

迁移策略：
1. 新创建的复合节点：直接在 `composite_nodes/{comp_id}/venv/` 创建
2. 已有复合节点：启动时自动将 venv 从 `nodes/` 移动到 `composite_nodes/`
3. 解压缩：venv 随整个 `composite_nodes/{comp_id}/` 一起删除

## 四、DAG 更新流程

```
用户展开 → 重连 → 折叠
         │
         ▼
  compress() 更新 composite.json 的 edges[]
         │
         ▼
  _sync_pipeline() ← 从 composite.json 重新生成 pipeline.json
  （不重新生成 orchestrator.py）
         │
         ▼
  下次启动 → orchestrator.py 读取最新 pipeline.json
```

`_sync_pipeline()` 是轻量操作：读 `composite.json` 的 `nodes` + `edges` → 写 `pipeline.json`。

## 五、生成器职责重划分

| 产物 | 何时生成/更新 | 生成器 |
|------|:---:|------|
| `composite.json` | compress + collapse | `_write_composite_config()` |
| `node_registry.json` | compress + start/stop | `_write_registry()` / `_update_registry_node()` |
| `pipeline.json` | compress + collapse + expand | `_sync_pipeline()`（新） |
| `orchestrator.py` | compress（首次） | `generate_orchestrator()`（仅改路径，逻辑不变） |
| `venv/` | compress | `CompositeEnvWorker`（仅改路径） |
| `output/*.json` | 运行时 | `DagRunner`（仅改路径） |

## 七、编排器脚本内 DAG 硬编码 → pipeline.json 迁移

### 旧 orchestrator.py 开头
```python
NODES = [{"name": "preprocess", "module": "nodes.preprocess.main"}, ...]
DAG = [{"from": "preprocess", "to": "inference"}]
```

### 新 orchestrator.py 开头
```python
import json
from pathlib import Path
PIPELINE = json.load(open(Path(__file__).parent / "pipeline.json"))
NODES = PIPELINE["nodes"]
DAG = PIPELINE["edges"]
```

生成器 `render_orchestrator_script()` 不再需要 `node_modules` 和 `dag` 参数：
```python
def render_orchestrator_script(comp_id: str) -> str:  # 移除 dag/node_modules 参数
    # ...
    # PIPELINE = json.load(open(Path(__file__).parent / "pipeline.json"))
```

## 九、验收标准

1. 新建复合节点 → venv 在 `composite_nodes/{comp_id}/venv/` 下，不在 `nodes/` 下
2. orchestrator.py 和 pipeline.json 在同一目录
3. DAG 变更 → 只更新 pipeline.json，不重新生成 orchestrator.py
4. 解压缩 → `rm -rf composite_nodes/{comp_id}/` 清空所有产物
5. 独立节点的 `nodes/` 目录完全不受影响
6. 已有复合节点的 venv 启动时自动迁移到新路径
7. 193 测试全部通过
