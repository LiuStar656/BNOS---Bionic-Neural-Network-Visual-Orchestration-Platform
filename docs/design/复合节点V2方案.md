# 复合节点 v2：输入输出接口 + 画布内展开/折叠 — 开发方案

## 一、需求概述

1. **输入输出接口**：复合节点展示输入/输出锚点
   - 输入端口：内部节点中 `listen_upper_file` 为空的节点（DAG 入度为 0）
   - 输出端口：DAG 所有叶子节点（全部暴露，分别连线）
2. **画布内展开/折叠**：双击复合节点展开为内部独立节点（由虚线框包围，整体移动），不再创建独立窗口
3. **语言判断组件**：自动识别节点语言，工厂模式选择 builder，当前先实现 Python
4. **展开状态下完全可编辑**：可修改连线、节点配置

## 二、画布内展开/折叠方案（核心变更）

### 2.1 交互流程

```
双击 CompositeNodeItem
  │
  ├─ 当前是折叠状态 ──→ 展开
  │   1. 隐藏 CompositeNodeItem
  │   2. 显示内部 NodeItem（从 nodes_data 读取最新 config）
  │   3. 恢复 original_positions（相对于复合节点中心偏移）
  │   4. 绘制虚线包围框（CompositeGroupFrame）
  │   5. 内部连线正常显示
  │   6. "被截断的外部连线"用虚线灰色显示
  │
  └─ 当前是展开状态 ──→ 折叠
      1. 隐藏内部 NodeItem
      2. 移除包围框
      3. 恢复 CompositeNodeItem（锚点自动刷新）
      4. 保存内部节点的新位置到 original_positions
```

### 2.2 CompositeGroupFrame（虚线包围框）

```
CompositeGroupFrame(QGraphicsRectItem)
  ├── 虚线边框，颜色 #4ec9b0（复合节点绿）
  ├── 半透明填充 rgba(78, 201, 176, 0.05)
  ├── 圆角矩形
  ├── 左上角标签："复合节点: xxx"
  ├── 工具栏按钮（悬浮在框边缘拉伸时保持在固定位置）：
  │   ├── [折叠] — 收起复合节点
  │   └── [编辑模式] — 切换只读/编辑
  └── 自动调整大小：监听内部节点位置变化，重新计算 boundingRect
```

### 2.3 整体移动机制

当展开状态下任何一个内部节点被拖拽移动时：

```
NodeItem.mouseMoveEvent → delta = new_pos - old_pos
  → 遍历所有内部节点 node.setPos(node.pos() + delta)
  → CompositeGroupFrame 自动重新计算 boundingRect()
```

实现方式：利用已有的 `NodeGroupManager` + 新的 `move_group_by_delta()` 方法。

### 2.4 展开状态下的连接规则

| 操作 | 行为 |
|------|------|
| 内部节点 A → 内部节点 B 连线 | 允许，写入 config.json |
| 外部节点 X → 内部节点 A 连线 | 先连到复合节点的输入锚点，内部自动路由到 A |
| 内部节点 B → 外部节点 Y 连线 | 从复合节点的输出锚点引出 |
| 拖拽内部节点移出框外 | 阻止，自动弹回框内 |

### 2.5 展开/折叠数据流

```
折叠 → 展开：
  node_clusters.json → _composites[comp_id] → 读取 internal_nodes config
  → 创建/恢复 NodeItem → 恢复 original_positions → 画 GroupFrame

展开 → 折叠：
  收集 internal_nodes 当前位置 → 更新 original_positions
  → 保存 node_clusters.json → 清除 NodeItem → 画 CompositeNodeItem
```

## 三、输入输出接口方案

### 3.1 端口识别

```
输入端口 = { n | n ∈ internal_nodes, listen_upper_file 为空 }
输出端口 = { n | n ∈ internal_nodes, n 是 DAG 叶子节点 }
```

### 3.2 数据结构

`node_clusters.json`：

```json
{
  "composite_xxx": {
    "...现有字段...": "",
    "input_ports": [
      {"internal_node": "node_a", "port_id": "in_0", "port_name": "输入1"},
      {"internal_node": "node_b", "port_id": "in_1", "port_name": "输入2"}
    ],
    "output_ports": [
      {"internal_node": "node_c", "port_id": "out_0", "port_name": "输出1"},
      {"internal_node": "node_d", "port_id": "out_1", "port_name": "输出2"}
    ],
    "language": "python"
  }
}
```

### 3.3 CompositeNodeItem 锚点渲染

- 左侧：每个输入端口一个绿色 `AnchorItem`（10px），端口名显示在左侧
- 右侧：每个输出端口一个红色 `AnchorItem`（10px），端口名显示在右侧
- 锚点垂直均匀分布
- 矩形高度根据端口数量自适应：
  ```
  min_height = max(60, max(input_count, output_count) * 25 + 20)
  ```

### 3.4 外部连线支持

```
外部节点 X → 复合节点 input_0
  → 映射到内部内部节点 node_a 的 listen_upper_file = "../X/output.json"

复合节点 output_0 → 外部节点 Y
  → 映射到内部节点 node_c 是 orchestra 的数据出口
  → Y 的 listen_upper_file = "../复合节点/output.json"
```

连线持久化不需特殊处理，`CanvasConnections.create_edge()` 照常工作，因为复合节点的 port 就像普通节点一样注册在 `AnchorManager` 中。

## 四、语言判断组件

### 4.1 LanguageDetector

**文件**：`ui/core/node/language_detector.py`

检测逻辑（按优先级）：
1. 读取 `start.json` 的 `entry` 字段扩展名 → `.py`=python, `.rs`=rust, `.js`=javascript
2. 目录特征文件：`requirements.txt` → python, `Cargo.toml` → rust, `package.json` → javascript
3. 文件扫描：stat 所有 .py/.rs/.js 按数量判定

```python
class LanguageDetector:
    @staticmethod
    def detect(node_path: str) -> str: ...
    @staticmethod 
    def detect_multi(node_paths: list[str]) -> str: ...
```

## 五、实施步骤

| 步骤 | 说明 | 文件 | 复杂度 |
|------|------|------|--------|
| **Step 1** | LanguageDetector | `language_detector.py` + 测试 | 低 |
| **Step 2** | CompositeNodeFactory + PythonBuilder | `composite_factory.py` + 重构 `composite_node.py` | 中 |
| **Step 3** | 端口识别 + 持久化 | `composite_node.py` | 中 |
| **Step 4** | CompositeNodeItem 锚点渲染 | `composite_node_item.py` | 中 |
| **Step 5** | 外部连线支持（复合节点锚点可连线） | `canvas_connections.py` | 中 |
| **Step 6** | CompositeGroupFrame 包围框 | 新文件 `group_frame.py` | 中 |
| **Step 7** | 展开折叠逻辑（核心） | `composite_node.py` + `canvas_view.py` | **高** |
| **Step 8** | 整体移动 + 位置同步 | `canvas_event_handlers.py` + `NodeGroupManager` | 中 |
| **Step 9** | 展开状态连线规则（内部连线 + 截断连线） | `canvas_connections.py` | 中 |
| **Step 10** | i18n + 测试 | `i18n/` + `tests/` | 低 |

### 执行顺序

```
Step 1 → Step 2 (语言组件，低风险)
  ↓
Step 3 → Step 4 → Step 5 (端口体系，外观先到位)
  ↓
Step 6 → Step 7 → Step 8 (展开折叠核心)
  ↓
Step 9 → Step 10 (连线规则 + 收尾)
```

## 六、对比原方案的变更

| 原方案 | 新方案 | 原因 |
|--------|--------|------|
| 独立窗口 `CompositeCanvasWindow` | 画布内展开 + `CompositeGroupFrame` | 用户反馈 |
| 子画布只读连线 | 展开状态完全可编辑 | 用户反馈 |
| orchestrator 运行时端口映射 | 不变，仍然需要 | — |
| 10 步 | 10 步，内容调整 | 步骤数不变 |

## 七、风险评估

| 风险 | 等级 | 缓解 |
|------|------|------|
| 展开状态下拖拽多节点同步性能 | 中 | 使用 `QSignalBlocker` + 节流（16ms = 60fps） |
| 展开状态下连线与现有连线逻辑冲突 | 高 | 连线时检查 `is_expanded_composite`，走独立分支 |
| composite_node.py 重构回归 | 中 | 保留旧方法 + `deprecated` 标记 |
| CompositeNodeItem 高度自适应端口数 | 低 | 每次端口变更时 `_update_geometry()` |
