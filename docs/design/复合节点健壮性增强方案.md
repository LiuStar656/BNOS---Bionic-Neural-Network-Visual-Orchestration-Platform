# 复合节点健壮性增强方案

## 一、性能：展开态批量拖拽 → 末端批量更新

### 根因

[canvas_event_handlers.py](file:///f:/Bionic Neural Network Program Operating System/ui/canvas/mixins/canvas_event_handlers.py#L348) `_sync_composite_group_movement()` 在**每次 `mouseMoveEvent`**（第 115 行）中被调用，对 20+ 个内部节点做 `setPos` + frame 更新 + anchor 同步，每帧触发 N 次重绘。

### 修复

将"首帧锚点快照 + 逐帧同步"改为**"首帧锚点快照 + 拖拽中仅移动可见项 + 释放时批量持久化"**：

**实现**：在 `mouseReleaseEvent` 末尾，对所有展开中的复合节点调用批量位置快照写入 `node_clusters.json`。拖拽中不再逐帧更新 anchor 字典——只移动 `QGraphicsItem` 让 Qt 自己处理重绘。

```python
# canvas_event_handlers.py — mousePressEvent 变动
def _prepare_composite_drag_anchor(self, item):
    # ... 同现有逻辑，但 anchor 只摄入不写回 ...
    if node_name not in node_names:
        continue
    anchor = {}
    for n in node_names:
        node_item = self.canvas.nodes.get(n)
        if node_item and node_item.isVisible():
            anchor[n] = (node_item.pos().x(), node_item.pos().y())
    comp["_drag_anchor_positions"] = anchor
    return

# canvas_event_handlers.py — _sync_composite_group_movement 变动
def _sync_composite_group_movement(self):
    # ... 逐帧移动逻辑保持不变，但去掉第 412 行的 anchor 写回 ...
    # 将 anchor[n] = (orig[0] + drag_dx, orig[1] + drag_dy) 删除
    pass  # 不再每帧写回 anchor

# canvas_event_handlers.py — mouseReleaseEvent 新增
def _commit_composite_drag_positions(self):
    """拖拽释放后批量写入最终位置到 node_clusters.json"""
    mgr = getattr(self.canvas, "_composite_manager", None)
    if not mgr:
        return
    any_changed = False
    for comp_id, comp in mgr._composites.items():
        if not comp.get("_expanded"):
            continue
        for n in comp.get("nodes", []):
            item = self.canvas.nodes.get(n)
            if item and item.isVisible():
                comp_pos = comp.setdefault("_internal_positions", {})
                comp_pos[n] = {"x": item.pos().x(), "y": item.pos().y()}
                any_changed = True
    if any_changed:
        mgr.save_debounced()
```

**效果**：拖拽帧率从随节点数 O(N) 退化改善为 O(1)（仅 Qt 自然重绘）。位置持久化延迟到拖拽结束，对用户无感知。

### 2.1 orchestrator 读写权限 / 磁盘满

### 2.3 展开态 config 外部修改冲突

**场景**：用户展开复合节点，然后在 IDE 中手动改 `nodes/xxx/config.json`，再折叠——`_sync_configs_for_collapse` 读到的 config 不是展开时的原始值。

**根因**：`_sync_configs_for_collapse` 直接读当前磁盘上的 config，无基线对比。

**修复**：展开时缓存 config 快照，折叠时对比差异，有冲突则弹窗询问。

```python
# composite_node.py — _sync_configs_for_expand 末尾新增
def _snapshot_internal_configs(self, comp_id, node_names):
    snap = {}
    for n in node_names:
        cfg_path = Path(self._project_path) / "nodes" / n / "config.json"
        try:
            snap[n] = cfg_path.read_text(encoding="utf-8")
        except Exception:
            snap[n] = None
    self._composites[comp_id]["_config_snapshot"] = snap

# composite_node.py — _sync_configs_for_collapse 开头新增
def _check_config_conflicts(self, comp_id, node_names) -> list[str]:
    """返回被外部修改的节点名列表"""
    snap = self._composites.get(comp_id, {}).get("_config_snapshot", {})
    conflicts = []
    for n in node_names:
        cfg_path = Path(self._project_path) / "nodes" / n / "config.json"
        try:
            current = cfg_path.read_text(encoding="utf-8")
        except Exception:
            current = None
        if snap.get(n) is not None and current != snap[n]:
            conflicts.append(n)
    return conflicts
```

冲突时调用 `themed_message("warning", f"以下节点 config 被外部修改: {conflicts}\n是否覆盖外部修改？")`。

**改动量**：+35 行。

## 三、分布式预留扩展点

### 当前状态

复合节点全部逻辑为本地画布耦合——`_apply_morph` 直接操作 `QGraphicsItem`，`start_inprocess` 用 `subprocess.Popen`，`_sync_configs` 读写本地 `config.json`。

### 修复：`CompositeNode` 增加 `execute(self, comp_id) -> bool` 抽象

```python
# composite_node.py 新增
def execute(self, comp_id: str) -> bool:
    """Unified execution entry. Routes to local or remote based on config."""
    comp = self._composites.get(comp_id)
    if not comp:
        return False

    transport = comp.get("transport", "local")  # "local" | "ssh" | "grpc" | ...
    if transport == "local":
        return self._execute_local(comp_id)
    else:
        handler = get_transport_handler(transport)
        return handler.execute(comp_id, comp)

def _execute_local(self, comp_id: str) -> bool:
    """Current logic: decide inprocess vs process and run."""
    runtime = comp.get("runtime", "inprocess")
    if runtime == "inprocess":
        ok, _ = self.start_inprocess(comp_id)
    else:
        ok, _ = self.start_process_mode(comp_id)
    return ok
```

```python
        # 2. ssh remote "python -m bnos_runtime ..."
        ...
```

**改动量**：`composite_node.py` +30 行（重构现有调用路径）+ `transports/` 目录为未来占位（空文件，仅存 ABC）。

## 四、编排器缓存与断点续跑

### 根因

`render_orchestrator_script`（[composite_orchestrator.py](file:///f:/Bionic Neural Network Program Operating System/ui/core/node/composite_orchestrator.py#L14)）生成的脚本执行 `run()` 后直接退出——无中间结果缓存，节点 3 报错需从节点 1 重来。

### 修复：双策略

#### 策略 A：子节点 output.json 作为天然缓存（轻量，立即可做）

编排器在执行每个子节点前先检查其 `output.json` 是否存在且时间戳晚于 `orchestrator.py`，若存在则跳过执行。

```python
# orchestrator 模板中 run() 方法变动
def run(self, external_input=None):
    if self._failed:
        ...
    ctx = {}
    for node_name in self._topo_sort():
        # 缓存检查：output.json 是否存在
        cached = self._try_read_cache(node_name)
        if cached is not None:
            print(f"[{comp_id}] SKIP {node_name} (cached)")
            ctx[node_name] = cached
            continue
        # ... 正常执行
        out = self._modules[node_name].process(inp)
        ctx[node_name] = out
        self._write_output(node_name, out)

def _try_read_cache(self, node_name):
    for n in NODES:
        if n["name"] == node_name:
            path = PROJECT_ROOT / n["path"] / "output.json"
            if path.exists():
                try:
                    data = json.loads(path.read_text(encoding="utf-8"))
                    if "run_id" in data:
                        return {k: v for k, v in data.items() if k != "run_id"}
                except Exception:
                    pass
    return None
```

**用法**：节点 3 报错 → 修 `main.py` → 重启 → 节点 1/2 跳过，直接从节点 3 续跑。

**改动量**：`composite_orchestrator.py` 模板 +16 行。

#### 策略 B：failed 标记文件 + `--retry` flag（后续）

略，P2 实现。在 failed 节点目录创建 `.failed` 标记文件，下一次执行时检查并只重跑失败节点。
