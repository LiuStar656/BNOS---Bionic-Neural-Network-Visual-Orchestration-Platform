# 复合节点监控与日志修复方案

## 问题

当前复合节点（inprocess 模式）在运行时是监控黑洞：

| 问题 | 根因 | 影响 |
|------|------|------|
| **折叠态无资源显示** | `CompositeNodeItem` 不继承 `NodeItem`，无 `NodeStatusWidget`，不订阅 `node_state_updated` 信号 | 画布上看不到 CPU/MEM |
| **无日志文件** | `start_inprocess()` 的 `stdout=subprocess.PIPE` 不落盘 | 右键 View Log 为空 |
| **PID 路径不识别** | `get_node_pid()` 只查 `{node_path}/.pid`，不知道 `__composite_{id}.pid` | 资源采集器找不到复合节点进程 |

### 变更清单

| 文件 | 改动 | 行数 |
|------|------|:---:|
| `composite_node.py` | `start_inprocess()` — PIPE 改落盘 + 日志文件 | +15 |
| `composite_node.py` | 新增 `_composite_log_paths()` / `stop_composite_monitoring()` | +25 |
| `composite_node_item.py` | 新增 `NodeStatusWidget` 集成 + 信号连接 | +60 |

**总计：约 120 行**

### 不改动

- `polling_manager.py` — 已有 `node_health` 和 `node_logs` 任务，复合进程 Popen 后会自动检测
- `ResourceMonitor` / `PerformancePanel` — 通过 `node_state_updated` 信号传递，无需感知节点类型
- `NodeMonitor` — 同上
- 复合节点 process 模式 — 内部节点以独立进程启动，监控正常（无需改动）

## 详细设计

### 1. `start_inprocess()` — 日志落盘

```
当前:
  stdout=subprocess.PIPE
  stderr=subprocess.PIPE
  0.3s 后从 PIPE 读 stderr（仅用于启动失败排查）

改为:
  stdout=open(comp_dir/logs/composite_output.log, "w")
  stderr=open(comp_dir/logs/composite_error.log, "w")
  不再读 PIPE（日志已在文件中）
```

日志文件路径约定：
```
nodes/image_pipeline/logs/
├── composite_output.log    ← orchestrator stdout（新）
├── composite_error.log     ← orchestrator stderr（新）
└── listener.log            ← 已有（但可能为空）
```

与普通节点的 `node_output.log` / `node_error.log` 命名风格一致。

### 2. `CompositeNodeItem` — 资源监控集成

新增 3 个方法：

```
_connect_monitoring()
  → 连接 resource_monitor.node_state_updated 信号
  → 信号到达时更新 _status_widget

_get_composite_pid() → int | None
  → 读取 project_root/__composite_{comp_id}.pid
  → 返回 orchestrator 进程 PID

_update_composite_status(cpu: float, mem_mb: float, status: str)
  → 更新 NodeStatusWidget 显示
  → 更新 status 指示符（保持画布上 ▸ 折叠按钮右侧）
```

`NodeStatusWidget` 只在 **折叠态 + 运行中** 时显式。展开后内部节点自身有监控部件。

### 3. `SystemResourceCollector.get_node_pid()` — PID 查找

```
当前:
  pid_file = node_path / ".pid"
  if not pid_file.exists(): return None

改为:
  pid_file = node_path / ".pid"
  if pid_file.exists(): return int(pid_file.read_text())

  # 复合节点回退路径
  comp_pid_file = project_root / f"__composite_{comp_id}.pid"
  if comp_pid_file.exists(): return int(comp_pid_file.read_text())

  return None
```

`comp_id` 从 node_path 的父目录名推导（复合节点目录名即 comp_id）。

### 4. `node_list_ops.py` — 日志查看

```
当前:
  log_file = node_path / "logs" / "listener.log"

改为:
  if is_composite:
      log_files = [
          node_path / "logs" / "composite_output.log",
          node_path / "logs" / "composite_error.log",
      ]
  else:
      log_files = [node_path / "logs" / "listener.log"]
```

`is_composite` 通过 `node_clusters.json` 存在性判断。

## 验收标准

| # | 检查项 | 预期 |
|---|--------|------|
| 1 | 压缩后启动复合节点，折叠态画布上显示 CPU/MEM | 数值 > 0，随刷新变化 |
| 2 | `__composite_{id}.pid` 文件被 `get_node_pid()` 正确读取 | `psutil.Process(pid)` 返回进程对象 |
| 3 | 复合节点目录下生成 `logs/composite_output.log` | 包含 orchestrator 的 print 输出 |
| 4 | 右键复合节点 → View Log 显示日志内容 | 非空，包含子节点运行日志 |
| 5 | 复合节点停止后 CPU/MEM 归零或隐藏 | status = stopped |
| 6 | 快速停止后重启，无僵尸进程残留 | `__composite_{id}.pid` 正确更新 |
| 7 | 展开态内部节点监控正常（回归） | 内部节点各自有 NodeStatusWidget |
| 8 | pytest 全绿 | 193 ± N 通过 |
