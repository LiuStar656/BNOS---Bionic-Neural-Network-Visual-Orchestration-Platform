# 复合节点子节点状态机方案

## 一、问题分析

### 1.1 问题描述

当前复合节点子节点存在以下配置同步问题：

| 问题编号 | 问题描述 | 影响范围 |
|----------|----------|----------|
| P0-1 | 删除复合节点与外部节点的连线后，配置文件没有更新字段 | 连线删除 |
| P0-2 | 外部节点连接复合节点后展开，子节点的 `listen_upper_file` 没有连接外部节点 | 展开同步 |
| P0-3 | 展开状态下连接子节点到外部节点，折叠后复合节点配置文件没有写入外部节点路径 | 折叠同步 |
| P0-4 | 展开状态下连接子节点到外部节点，折叠后丢失线条，再展开提示"已连接" | 连线状态管理 |

### 1.2 根本原因

当前复合节点子节点的状态管理是**隐式**的，分散在多个函数中：

- `_sync_configs_for_expand` — 展开时配置同步
- `_sync_configs_for_collapse` — 折叠时配置同步
- `_morph_composite_to_internal_edges` — 展开时连线变形
- `_morph_internal_to_composite_edges` — 折叠时连线变形

这种分散式管理导致：
1. 状态转换不明确，容易遗漏边界情况
2. 竞态条件：删除连线和重新连接之间的时序问题
3. 状态不一致：UI 显示状态和配置文件状态不同步

### 1.3 现有状态机组件分析

| 组件 | 文件 | 用途 | 是否可复用 |
|------|------|------|------------|
| `StateMachine` | `ui/core/state/base.py` | 通用有限状态机基类 | ✅ 完全可复用 |
| `CompositeLifecycleSM` | `ui/core/state/composite_lifecycle.py` | 复合节点生命周期（启动/停止/崩溃） | ❌ 不适用 |
| `NodeRuntimeSM` | `ui/core/state/node_runtime.py` | 节点运行时状态 | ❌ 不适用 |
| `EdgeInteractionSM` | `ui/core/state/edge_interaction.py` | 边交互状态 | ❌ 不适用 |

**结论**：`StateMachine` 基类完全可复用，但需要创建新的状态机类来处理复合节点子节点的状态。

## 二、方案设计

### 2.1 核心思路：外部状态机管理器

不将状态机嵌入到 `NodeItem` 中，而是创建一个独立的**状态机管理器**，通过信号与现有代码交互，实现状态管理与业务逻辑的解耦合。

```
┌─────────────────────────────────────────────────────────────┐
│                    CompositeStateManager                    │
│  ┌───────────────────────────────────────────────────────┐  │
│  │  管理所有复合节点子节点的状态机                         │  │
│  ├───────────────────────────────────────────────────────┤  │
│  │  {node_name: CompositeChildSM}                        │  │
│  │                                                       │  │
│  │  + get_state(node_name) → 当前状态                    │  │
│  │  + handle_event(node_name, event, data) → 触发事件    │  │
│  │  + register(node_name) → 注册子节点                   │  │
│  │  + unregister(node_name) → 注销子节点                 │  │
│  └───────────────────────────────────────────────────────┘  │
└─────────────────────────────────────────────────────────────┘
                              │
                              ▼
              ┌─────────────────────────────┐
              │     信号连接（不嵌入代码）   │
              ├─────────────────────────────┤
              │  state_changed → 现有代码   │
              │  需要同步配置时触发          │
              └─────────────────────────────┘
```

### 2.2 状态定义

```python
class CompositeChildState(str, Enum):
    """复合节点子节点的状态。"""
    
    FREE = "free"                    # 自由状态（不在复合节点中）
    COMPOSITE_COLLAPSED = "composite_collapsed"  # 在复合节点中，复合节点折叠
    COMPOSITE_EXPANDED = "composite_expanded"    # 在复合节点中，复合节点展开
```

### 2.3 事件定义

| 事件 | 触发时机 | 所属文件 |
|------|----------|----------|
| `add_to_composite` | 节点被添加到复合节点 | `composite_node.py` |
| `remove_from_composite` | 节点从复合节点移除 | `composite_node.py` |
| `expand_composite` | 复合节点展开 | `composite_node.py` |
| `collapse_composite` | 复合节点折叠 | `composite_node.py` |
| `connect_external` | 连接外部节点 | `canvas_connections.py` |
| `disconnect_external` | 断开外部连接 | `canvas_connections.py` |

### 2.4 状态转换图

```
FREE ──add_to_composite──→ COMPOSITE_COLLAPSED
     ←──remove_from_composite───┘
               ↑
               │ collapse_composite
               ↓
COMPOSITE_EXPANDED ──expand_composite──┘
     │
     ├── connect_external → 更新子节点配置 + 记录路由
     └── disconnect_external → 清除子节点配置 + 清除路由
```

### 2.5 状态转换表

| 事件 | 源状态 | 目标状态 | Guard | Action |
|------|--------|----------|-------|--------|
| `add_to_composite` | FREE | COMPOSITE_COLLAPSED | - | `_on_add_to_composite` |
| `remove_from_composite` | COMPOSITE_COLLAPSED | FREE | - | `_on_remove_from_composite` |
| `remove_from_composite` | COMPOSITE_EXPANDED | FREE | - | `_on_remove_from_composite` |
| `expand_composite` | COMPOSITE_COLLAPSED | COMPOSITE_EXPANDED | - | `_on_expand_composite` |
| `collapse_composite` | COMPOSITE_EXPANDED | COMPOSITE_COLLAPSED | - | `_on_collapse_composite` |
| `connect_external` | COMPOSITE_EXPANDED | COMPOSITE_EXPANDED | - | `_on_connect_external_expanded` |
| `disconnect_external` | COMPOSITE_EXPANDED | COMPOSITE_EXPANDED | - | `_on_disconnect_external_expanded` |
| `connect_external` | COMPOSITE_COLLAPSED | COMPOSITE_COLLAPSED | - | `_on_connect_external_collapsed` |
| `disconnect_external` | COMPOSITE_COLLAPSED | COMPOSITE_COLLAPSED | - | `_on_disconnect_external_collapsed` |

## 三、关键实现细节

### 3.1 配置同步逻辑

#### 3.1.1 折叠时同步（COMPOSITE_EXPANDED → COMPOSITE_COLLAPSED）

```python
def _on_collapse_composite(self, sm):
    """折叠时：从子节点同步到复合节点"""
    if sm.external_connections:
        for port_name, source_path in sm.external_connections.items():
            self._composite_manager.set_input_routing(
                sm.comp_id, port_name, source_path
            )
        # 清除子节点配置
        self._clear_child_config(sm.node_name)
```

#### 3.1.2 展开时同步（COMPOSITE_COLLAPSED → COMPOSITE_EXPANDED）

```python
def _on_expand_composite(self, sm):
    """展开时：从复合节点同步到子节点"""
    routing = self._composite_manager._get_port_routing(sm.comp_id)
    # 查找该子节点对应的端口路由
    port_to_internal = {}
    comp = self._composite_manager._composites.get(sm.comp_id, {})
    for p in comp.get("input_ports", []):
        port_to_internal[p.get("port_name", "")] = p.get("internal_node", "")
        if p.get("port_name") == "data":
            port_to_internal["default"] = p.get("internal_node", "")
    
    for port_name, route in routing.get("input", {}).items():
        internal_node = port_to_internal.get(port_name)
        if internal_node == sm.node_name:
            source_path = route.get("source_output_path", "")
            if source_path:
                self._set_child_config(sm.node_name, source_path, port_name)
                sm.external_connections[port_name] = source_path
```

### 3.3 删除连线时的同步

```python
def _on_disconnect_external_expanded(self, sm, port_name):
    """展开状态下断开外部连接"""
    # 清除子节点配置
    self._clear_child_config(sm.node_name, port_name)
    # 清除状态机中的记录
    if port_name in sm.external_connections:
        del sm.external_connections[port_name]
    # 清除复合节点路由
    self._composite_manager.clear_input_routing(sm.comp_id, port_name)
    # 立即同步到配置文件（消除延迟写入导致的竞态条件）
    self._composite_manager._sync_routing_to_config(sm.comp_id)
```

## 七、风险评估

| 风险 | 风险等级 | 缓解措施 |
|------|----------|----------|
| 状态机与现有逻辑冲突 | 高 | 逐步替换，保持向后兼容 |
| 删除连线时的竞态条件 | 中 | 删除时立即同步配置文件 |
| 状态机性能影响 | 低 | 状态机开销很小，可忽略不计 |
| 多个子节点状态不一致 | 中 | 统一由状态管理器管理 |

## 八、方案优势

| 维度 | 优势 |
|------|------|
| **复用性** | 完全复用现有的 `StateMachine` 基类 |
| **非侵入性** | 不嵌入到 `NodeItem` 中，通过外部管理器调用 |
| **可测试性** | 状态机可以单独测试，不依赖 UI 组件 |
| **可扩展性** | 可以轻松添加新的状态和事件 |
| **解耦合** | 状态管理与业务逻辑分离 |
| **一致性** | 所有状态转换都有明确定义，避免隐式状态 |
