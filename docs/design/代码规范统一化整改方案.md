# BNOS 代码规范统一化整改方案

> 生成日期：2026-07-12 | 审查范围：全项目 170+ 源文件

---

## 一、背景

对项目 `ui/`、`tests/`、根目录共 7 大模块进行了全面代码审查。结论：**项目架构层面质量较高**（分层清晰、Mixin 解耦、DI 容器已引入），但**缺乏统一的编码规范文档和自动化检查工具**，导致以下 9 个维度存在明显不一致。

---

## 二、已发现的不一致问题

### 2.1 Logger 使用不一致（严重）

| 模式 | 文件数 | 示例文件 |
|------|--------|----------|
| `from ui.core.logger import logger` | 81 个 | 主流用法 |
| `import logging; logger = logging.getLogger(__name__)` | 2 个 | `ui/core/i18n/i18n.py`、`ui/core/i18n/translation_keys.py` |
| 不使用 logger | 15 个 | `tests/` 全部 |

**影响**：i18n 模块绕过了 BNOS 统一日志系统（SafeStreamHandler、FrequencyFilter、日志轮转），其日志不会写入 `logs/bnos.log`。

### 2.2 i18n 导入路径不一致（中等）

| 模式 | 文件数 | 示例文件 |
|------|--------|----------|
| `from ui.core.i18n import t` | 绝大多数 | 公共 API |
| `from ui.core.i18n.i18n import init_i18n` | 1 个 | `ui/core/services/core_process.py` |
| `from ui.core.i18n.i18n import t` | 1 个 | `ui/core/project/project_manager.py` |

**影响**：绕过了 `__init__.py` 的公共 API，破坏封装性。

### 2.3 `from __future__ import annotations` 使用率极低

仅 8 个文件使用了此特性（commands 模块 + `anchor_manager.py` + `history_panel.py`），占全部文件的不足 5%。该语句可以：
- 让所有注解变为延迟求值，避免循环导入
- 允许使用 `str | None` 替代 `Optional[str]`（PEP 604）

### 2.4 Docstring 格式不统一

| 风格 | 示例文件 |
|------|----------|
| Google 风格（含 Args/Returns） | `node_registry.py`、`anchor_manager.py` |
| 无参数文档 | `event_bus.py`、`thread_pool.py` |
| 中文描述 + 英文描述混用 | `bnos_console.py`（中文）、`lifecycle.py`（英文） |
| 仅一行简短描述 | `draw_layer.py`、`terminal_widget.py` |

### 2.5 注释语言混乱

- 中文注释（含中文标点 `——`）：`__main__.py`、`state.py`、`anchor_manager.py`、`canvas_colors.py`、`canvas_layout.py`、`project_manager.py`
- 全英文注释：`lifecycle.py`、`actions.py`、大部分 `core/` 模块
- 同文件内中英混用：`state.py`（英文 docstring + 中文行内注释）

### 2.6 `print()` 残留于生产代码

| 文件 | 出现次数 |
|------|----------|
| `ui/creators/node_creator_manager.py` | 10 处 |
| `ui/core/node/composite_orchestrator.py` | 8 处 |
| `ui/core/i18n/translation_keys.py` | 5 处 |
| `ui/core/services/core_process.py` | 2 处 |
| `ui/core/config/validators.py` | 1 处 |
| **合计** | **26 处** |

### 2.7 类型注解覆盖不均

| 特征 | 文件 | 评估 |
|------|------|------|
| 完善的类型注解 | `event_bus.py`、`di.py`、`anchor_manager.py` | 优秀 |
| 几乎无类型注解 | `node_item.py`、`state.py`、`actions.py` | 缺失 |
| 显式 `# type: ignore` / `# pyright:` | `action_registry.py`（7 处） | 类型检查被绕过 |

### 2.8 `os.path` vs `pathlib.Path` 混用

- `from pathlib import Path` 仅 6 个文件使用
- 58 个文件使用 `os.path.abspath` / `os.path.dirname` / `os.path.join`（共 336 处）
- 同一文件内两种 API 混用（如 `project_manager.py`）

### 2.9 测试文件风格不统一

- 测试文件顶层 docstring 用中文，源码模块 docstring 中英混用
- 测试文件不导入项目 logger
- 部分用 `class TestXxx:` 组织，部分用模块级函数（如 `test_validators.py`）

## 三、整改方案

分 3 个阶段推进。

---

### 阶段一：零风险自动化（立即可执行）

**目标**：引入工具链，自动化检查，不改业务逻辑。

| 措施 | 工具 | 说明 |
|------|------|------|
| 添加 `pyproject.toml` | Ruff / isort | 统一配置代码格式化、import 排序、lint 规则 |
| 配置 `.editorconfig` | EditorConfig | 统一缩进、换行符、编码 |
| 添加 `.pre-commit-config.yaml` | pre-commit | 提交前自动执行 ruff check + ruff format |
| 添加 `pyrightconfig.json` | Pyright | 渐进式类型检查，从 `basic` 模式开始 |

#### `pyproject.toml`

```toml
[project]
name = "bnos"
version = "1.0.0"
requires-python = ">=3.11"

[tool.ruff]
target-version = "py311"
line-length = 120
exclude = ["venv", "codicon-source", ".git", "__pycache__", "build", "dist"]

[tool.ruff.lint]
select = [
    "E", "W",    # pycodestyle errors / warnings
    "F",         # pyflakes (未使用的导入、未定义的变量等)
    "I",         # isort (import 排序)
    "N",         # pep8-naming (命名规范)
    "UP",        # pyupgrade (现代化语法)
    "B",         # flake8-bugbear (常见错误)
    "T20",       # flake8-print (禁止 print())
]
ignore = [
    "E501",      # 行长度由 formatter 处理
]

[tool.ruff.lint.isort]
known-first-party = ["ui"]
combine-as-imports = true

[tool.ruff.lint.pep8-naming]
classmethod-decorators = ["classmethod"]

[tool.ruff.format]
quote-style = "double"
indent-style = "space"
docstring-code-format = true
```

#### `.editorconfig`

```ini
root = true

[*]
charset = utf-8
end_of_line = lf
insert_final_newline = true
trim_trailing_whitespace = true

[*.py]
indent_style = space
indent_size = 4
max_line_length = 120

[*.json]
indent_style = space
indent_size = 2

[*.md]
trim_trailing_whitespace = false
```

#### `.pre-commit-config.yaml`

```yaml
repos:
  - repo: https://github.com/astral-sh/ruff-pre-commit
    rev: v0.5.0
    hooks:
      - id: ruff
        args: [--fix]
      - id: ruff-format
```

#### `pyrightconfig.json`

```json
{
  "include": ["ui", "tests"],
  "exclude": ["venv", "codicon-source", "build", "dist"],
  "pythonVersion": "3.11",
  "typeCheckingMode": "basic",
  "reportMissingImports": false,
  "reportMissingTypeStubs": false,
  "reportUnknownMemberType": false,
  "reportUnknownArgumentType": false,
  "reportUnknownVariableType": false
}
```

### 阶段二：低风险统一（逐模块修复）

| 优先级 | 问题 | 整改措施 | 涉及文件 |
|--------|------|----------|----------|
| **P0** | Logger 不统一 | `i18n.py`、`translation_keys.py` 改为 `from ui.core.logger import logger` | 2 个 |
| **P0** | `print()` 残留 | 全部替换为 `logger.info/debug()` | 5 个 |
| **P0** | i18n 导入路径 | `core_process.py`、`project_manager.py` 改为 `from ui.core.i18n import t, init_i18n` | 2 个 |
| **P1** | Docstring 格式 | 统一采用 **Google 风格**，至少包含一段描述 + `Args`/`Returns`（如有） | 所有文件 |
| **P1** | 注释语言 | 确定策略：**docstring 和注释统一使用中文**（项目面向中文团队，且 i18n 中文优先） | 约 10 个文件 |
| **P1** | `from __future__ import annotations` | 全项目统一添加，同步将 `Optional[X]` → `X \| None`、`List[X]` → `list[X]` | 所有 `.py` |
| **P2** | `os.path` → `pathlib` | 新代码统一使用 `pathlib.Path`，旧代码渐进式迁移 | 58 个文件 |
| **P2** | `# type: ignore` 治理 | `action_registry.py` 中 7 处逐一修复或添加说明注释 | 1 个 |

## 四、编码规范速查

### 命名

| 类型 | 规则 | 示例 |
|------|------|------|
| 类名 | PascalCase | `NodeRegistry`、`EventBus` |
| 函数/方法 | snake_case | `start_node_process()` |
| 变量 | snake_case | `node_count` |
| 常量 | UPPER_SNAKE | `SERVER_NAME`、`MAX_UNDO` |
| 私有成员 | `_` 前缀 | `_nodes`、`_setup_ui()` |
| 内部模块 | `_` 前缀 | `_base.py`、`_shared/` |
| 模块/包 | snake_case | `canvas_view.py`、`node_control_service.py` |

### 导入顺序

```
1. 标准库        (import os, sys, json)
2. 第三方        (from PySide6.QtWidgets import ...)
3. 本地模块      (from ui.core.logger import logger)
```

每组之间空一行，组内按字母序排列。多行导入使用括号。

### 文档

- **格式**：Google-style docstring
- **语言**：中文
- **要求**：每个 public class 和 public function 必须有 docstring

### 日志

- **统一入口**：`from ui.core.logger import logger`
- **禁止**：`print()` 用于业务日志输出
- **级别**：`debug`（调试信息）< `info`（关键流程）< `warning`（可恢复异常）< `error`（需关注）

### 类型注解

- 每个文件首行后添加 `from __future__ import annotations`
- 公开 API 函数必须标注参数和返回值类型
- 新代码使用 `X | None` 代替 `Optional[X]`，`list[X]` 代替 `List[X]`
- 禁止裸 `# type: ignore`，必须附加说明原因

### 路径操作

- **新代码**：统一使用 `pathlib.Path`
- **旧代码**：渐进式迁移

## 五、执行步骤

### 第一步：基础设施（1-2 天）

1. 创建 `pyproject.toml`（含 Ruff 配置）
2. 创建 `.editorconfig`
3. 创建 `.pre-commit-config.yaml`
4. 创建 `pyrightconfig.json`
5. 安装 pre-commit hooks：`pre-commit install`
6. 运行全项目格式化：`ruff format .`
7. 运行全项目 lint 检查：`ruff check . --fix`
8. 修复 Ruff 报出的可自动修复问题

### 第二步：P0 问题修复（按模块逐个）

1. 修复 i18n 模块 logger 问题（2 个文件）
2. 替换所有 `print()` 为 logger（5 个文件）
3. 统一 i18n 导入路径（2 个文件）
4. 修复后运行测试确保无回归

### 第三步：渐进式完善（长期）

- 每次修改旧文件时，同步完成：
  - 添加 `from __future__ import annotations`
  - 补充 Google 风格 docstring
  - 补充类型注解
  - 将 `os.path` 替换为 `pathlib.Path`
- 保持 CI 绿色（ruff check 通过）
