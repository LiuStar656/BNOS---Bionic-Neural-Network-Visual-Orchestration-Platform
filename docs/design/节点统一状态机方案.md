# 节点统一状态机方案（评审修订版）

## 一、节点类型与问题分析

### 1.1 三种节点类型

当前系统存在三种节点类型，各有不同的行为特征和状态维度：

| 节点类型 | 类名 | 说明 | 配置文件 | 现有状态机 |
|----------|------|------|----------|------------|
| **独立节点** | `NodeItem` | 普通节点，不属于任何复合节点 | `node_config.json` | `NodeRuntimeSM` |
| **复合节点子节点** | `NodeItem` | 属于某个复合节点内部的子节点 | `node_config.json` | `NodeRuntimeSM` |
| **复合节点本身** | `CompositeNodeItem` | 复合节点作为整体存在于画布上 | `node_clusters.json` / `composite.json` | `CompositeLifecycleSM` |

### 1.2 三种节点的状态维度差异

| 状态维度 | 独立节点 | 复合节点子节点 | 复合节点本身 |
|----------|----------|----------------|--------------|
| 成员角色 | ✅ STANDALONE | ✅ COMPOSITE_CHILD | ✅ COMPOSITE |
| 可见性状态 | ✅（始终可见） | ✅ VISIBLE / HIDDEN_COLLAPSED | ✅ EXPANDED_MODE / COLLAPSED_MODE |
| 运行状态 | ✅ NodeRuntimeSM | ✅ NodeRuntimeSM | ✅ CompositeLifecycleSM |
| 上游连接状态 | ✅（直接 listen_upper_file） | ✅（子节点 listen_upper_file） | ✅（通过 _port_routing 代理） |
| 下游连接状态 | ✅ | ✅ | ✅ |
| 内部子节点管理 | ❌ | ❌ | ✅（子节点增删、入口切换） |

### 1.3 现有问题（按节点类型分）

#### 独立节点问题

| 问题 | 描述 |
|------|------|
| 删除连线配置残留 | 删除连线后 `listen_upper_file` 未及时清除，后续连接覆盖但不删除 |
| 连接状态与配置不同步 | 连接存在但配置中无记录，或配置中有记录但连线已删除 |

#### 复合节点子节点问题

| 问题 | 描述 |
|------|------|
| 展开后无外部连接 | 折叠状态连接复合节点，展开后子节点 `listen_upper_file` 为空 |
| 折叠后复合配置丢失 | 展开状态连接子节点，折叠后复合节点 `_port_routing` 未写入 |
| 折叠丢失线条 / 展开误判已连接 | 连线状态在折叠/展开时不一致 |
| 删除连线复合配置未更新 | 折叠状态删除连线，`_port_routing` 未清除（延迟写入竞态） |

#### 复合节点本身问题

| 问题 | 描述 |
|------|------|
| 展开/折叠状态独立管理 | 复合节点的展开折叠与子节点可见性状态未统一协调 |
| 子节点管理无状态约束 | 运行中仍可增删子节点、切换入口节点，可能导致不一致 |

## 二、方案设计（评审修订版）

### 2.1 核心架构：正交分层 + 状态/副作用分离

**设计原则**：
1. **正交维度独立**：成员角色、可见性、上游连接、下游连接、运行生命周期 — 五个完全独立的子状态机，同级并行，互不嵌套。
2. **状态与副作用分离**：Manager 只管状态合法性校验与状态切换；所有文件 I/O、子节点遍历、路由同步、UI 信号交给独立的 ActionService。
3. **数据流单向闭环**：

```
用户操作（菜单/连线/按钮）
       │
       ▼
 NodeStateManager.handle_event(event, node)
       │
       ├─ ① Guard 校验（is_allowed + 并发锁 + 防抖去重）
       ├─ ② 并行正交状态机切换（Membership / Visibility / Connection）
       ├─ ③ 运行状态机转发（NodeRuntimeSM / CompositeLifecycleSM）
       │
       ▼
 NodeStateActionService（副作用调度，可事务批量）
       │
       ├─ 读写配置文件（listen_upper_file / _port_routing）
       ├─ 批量子节点遍历（expand / collapse）
       ├─ 内存路由缓存事务（成功统一落盘，失败回滚）
       └─ 派发 state_changed 信号
       │
       ▼
 CanvasConnections 监听信号 → 连线变形 / 清理
 ParamPanel 监听信号 → 配置面板刷新
```

### 2.2 四层正交状态机（同级独立，无嵌套）

| 层级 | 状态机 | 状态枚举 | 说明 |
|------|--------|----------|------|
| L1 | **MembershipSM** | `STANDALONE` / `COMPOSITE_CHILD` / `COMPOSITE` | 成员角色（互斥三选一） |
| L2 | **VisibilitySM** | `VISIBLE` / `HIDDEN_COLLAPSED` | 画布可见性（独立维度） |
| L3 | **ConnectionSM** | Upstream: `DISCONNECTED`/`CONNECTED`<br>Downstream: `NO_OUTPUTS`/`HAS_OUTPUTS` | 上下游连接状态（独立维度） |
| L4 | **RuntimeSM（复用）** | `NodeRuntimeSM` / `CompositeLifecycleSM` | 运行生命周期（按节点类型选） |

> **评审修订1**：VisibilitySM 从 MembershipSM 内部剥离，升级为 L2 级平级正交状态机，边界更清晰。

## 五、核心组件详细设计（评审修订版）

### 5.1 NodeStateManager — 纯状态流转（不含副作用）

**文件**：`ui/core/state/node_state_manager.py`

> **评审修订3**：Manager 只做 ① 并发锁 / 防抖去重 / 非法事件兜底 ② Guard 校验 ③ 状态切换，不直接触碰任何配置文件与 UI。所有副作用交给 NodeStateActionService。

```python
class NodeStateManager(QObject):

    state_changed = Signal(str, dict, dict)   # node_name, old_full_state, new_full_state
    illegal_event = Signal(str, str, str)     # node_name, event, reason

    def __init__(self, composite_manager_ref):
        super().__init__()
        self._composite_mgr = composite_manager_ref
        self._action_svc = NodeStateActionService(self, composite_manager_ref)
        self._transition_table = build_transition_table()

        # 各正交子状态机
        self._membership_sms: dict[str, MembershipSM] = {}
        self._visibility_sms: dict[str, VisibilitySM] = {}
        self._connection_sms: dict[str, ConnectionSM] = {}
        self._runtime_sms: dict[str, Any] = {}  # NodeRuntimeSM | CompositeLifecycleSM

        # 并发防护（每节点状态锁 + 防抖时间窗）
        self._node_locks: dict[str, threading.Lock] = {}
        self._event_debounce_ms: dict[str, int] = {
            "expand": 150, "collapse": 150,
            "start": 300, "stop": 300,
        }
        self._last_event_at: dict[tuple[str, str], float] = {}

        # 调试观测
        self._audit_log: list[dict] = []  # 状态变更流水

    # ────────── 注册/注销 ──────────
    def register_standalone(self, node_name: str) -> None: ...
    def register_composite_child(self, node_name: str, comp_id: str) -> None: ...
    def register_composite(self, comp_id: str, child_names: list[str], entry: str) -> None: ...

    def unregister(self, node_name: str) -> None:
        """完整销毁流程，防止内存泄漏与脏数据残留。"""
        with self._acquire_lock(node_name):
            # 1. 断开信号监听
            # 2. 清空四维度 SM 实例
            del self._membership_sms[node_name]
            del self._visibility_sms[node_name]
            del self._connection_sms[node_name]
            if node_name in self._runtime_sms:
                del self._runtime_sms[node_name]
            # 3. 清理内存路由缓存（交给 ActionService）
            self._action_svc.clear_route_cache(node_name)
            # 4. 清理锁与防抖记录
            del self._node_locks[node_name]
            self._last_event_at = {k: v for k, v in self._last_event_at.items() if k[0] != node_name}

    # ────────── 统一事件入口（核心）──────────
    def handle_event(self, node_name: str, event: str, **kwargs) -> bool:
        lock = self._acquire_lock(node_name)           # 并发串行化
        try:
            if self._is_debounced(node_name, event):    # 防抖去重
                self._emit_illegal(node_name, event, "debounced duplicate")
                return False

            if not self._is_registered(node_name):      # 节点已销毁兜底
                self._emit_illegal(node_name, event, "node not registered")
                return False

            # 查找匹配的 transition key（按当前状态）
            key = self._match_transition_key(node_name, event)
            if key not in self._transition_table:
                self._emit_illegal(node_name, event, f"no rule for key={key}")
                return False

            rule = self._transition_table[key]

            # 执行所有 guard
            for g in rule.get("guard", []):
                if not g(self.get_state(node_name)):
                    self._emit_illegal(node_name, event, f"guard failed: {g}")
                    return False

            # 捕获旧状态快照
            old_state = self.get_state(node_name)

            # 执行状态切换（纯内存操作，不碰文件）
            for dim, (from_s, to_s) in rule["transition"].items():
                self._apply_transition(node_name, dim, from_s, to_s)

            # L4 运行状态机转发（start/stop 等）
            if event in ("start", "stop", "start_ok", "crash", ...):
                ok = self._forward_runtime_event(node_name, event, **kwargs)
                if not ok:
                    self._rollback_transitions(node_name, rule["transition"], old_state)
                    return False

            # 副作用调度（交给 ActionService，支持事务）
            action_name = rule["action"]
            transaction = rule.get("transaction", False)
            immediate_flush = rule.get("immediate_flush", False)

            if transaction:
                tx = self._action_svc.begin_transaction(node_name)
                try:
                    self._action_svc.invoke(action_name, node_name, **kwargs)
                    tx.commit()      # 内存缓存 → 一次性落盘
                except Exception as ex:
                    tx.rollback()      # 整体回滚内存缓存
                    self._rollback_transitions(node_name, rule["transition"], old_state)
                    self._emit_illegal(node_name, event, f"action exception: {ex}")
                    return False
            else:
                self._action_svc.invoke(action_name, node_name, **kwargs)
                if immediate_flush:
                    self._action_svc.flush_route_cache(node_name)

            # 捕获新状态 + 审计流水
            new_state = self.get_state(node_name)
            self._append_audit(node_name, event, old_state, new_state)

            # 派发信号（Canvas / UI 监听）
            self.state_changed.emit(node_name, old_state, new_state)
            return True
        finally:
            lock.release()
```

### 5.2 NodeStateActionService — 副作用调度（配置写盘/子节点遍历/路由同步）

**文件**：`ui/core/state/node_state_action_service.py`

> **评审修订4**：所有跨维度联动、文件 I/O、子节点遍历从 Manager 抽离到此服务，Manager 与 Action 职责严格分离。

```python
class NodeStateActionService:

    def __init__(self, mgr: "NodeStateManager", composite_mgr):
        self._mgr = mgr
        self._composite_mgr = composite_mgr
        self._route_cache = RouteCache()   # 内存事务缓冲
        self._tx_stack: list[Transaction] = []
        self._actions = self._register_actions()

    # ───── 事务机制（批量 expand/collapse 用）─────
    def begin_transaction(self, tx_owner: str) -> Transaction:
        tx = Transaction(self._route_cache, tx_owner)
        self._tx_stack.append(tx)
        return tx

    def flush_route_cache(self, node_name: str) -> None:
        """内存缓存 → 一次性写入 JSON（减少 IO 次数 + 原子性保障）。"""
        pending = self._route_cache.extract_pending(node_name)
        for comp_id, routing in pending.composite_routings.items():
            self._composite_mgr._write_port_routing(comp_id, routing)
        for node_path, value in pending.listen_upper_files.items():
            write_json_field(node_path, "listen_upper_file", value)

    def clear_route_cache(self, node_name: str) -> None:
        self._route_cache.clear(node_name)

    # ───── 副作用动作注册（与 TRANSITION_TABLE 的 action 字段对应）─────
    def _register_actions(self) -> dict[str, Callable]:
        return {
            "action_standalone_connect_upstream":      self._act_standalone_connect_upstream,
            "action_standalone_disconnect_upstream":   self._act_standalone_disconnect_upstream,
            "action_child_visible_connect_upstream":   self._act_child_visible_connect_upstream,
            "action_child_visible_disconnect_upstream":self._act_child_visible_disconnect_upstream,
            "action_child_hidden_connect_upstream":    self._act_child_hidden_connect_upstream,
            "action_child_expand_with_connection":     self._act_child_expand_with_connection,
            "action_child_collapse_with_connection":   self._act_child_collapse_with_connection,
            "action_composite_expand_batch":           self._act_composite_expand_batch,
            "action_composite_collapse_batch":         self._act_composite_collapse_batch,
            "action_composite_switch_entry":           self._act_composite_switch_entry,
            "action_compress_into_composite":          self._act_compress_into_composite,
            "action_decompress_preserve_connection":   self._act_decompress_preserve_connection,
        }

    def invoke(self, action_name: str, node_name: str, **kwargs) -> None:
        fn = self._actions[action_name]
        fn(node_name, **kwargs)

    # ───── 具体动作（示例 3 个）─────
    def _act_child_expand_with_connection(self, node_name: str) -> None:
        """COMPOSITE_CHILD + HIDDEN + CONNECTED → expand：从 _port_routing 同步到子节点 listen_upper_file。"""
        comp_id = self._mgr._membership_sms[node_name].comp_id
        conn_sm = self._mgr._connection_sms[node_name]
        routing = self._composite_mgr._get_port_routing(comp_id)
        port_to_internal = self._mgr._build_port_to_internal(comp_id)
        node_cfg_path = self._get_node_config_path(node_name)

        # 找到本节点对应的端口路由
        for port_name, route in routing.get("input", {}).items():
            internal_node = port_to_internal.get(port_name)
            if internal_node == node_name:
                src = route.get("source_output_path", "")
                # 先写入事务缓存（若是 batch expand，结束时统一 flush；单节点立即 flush）
                self._route_cache.set_listen_upper_file(node_cfg_path, src)
                conn_sm.upstream_node_name = extract_node(src)
                conn_sm.upstream_output_path = src
                conn_sm.upstream_port = port_name

    def _act_composite_expand_batch(self, comp_id: str) -> None:
        """COMPOSITE expand 批量事务：遍历子节点，逐个触发子节点 expand。"""
        child_names = self._mgr._membership_sms[comp_id].child_node_names
        for child in child_names:
            child_state = self._mgr.get_state(child)
            if child_state.connection.upstream == CONNECTED:
                self._act_child_expand_with_connection(child)
            else:
                # 无连接的直接切可见性
                self._mgr._visibility_sms[child].apply_transition(
                    HIDDEN_COLLAPSED, VISIBLE, "batch_expand")
        # 事务 commit 时 Manager 已调用 flush

    def _act_child_visible_disconnect_upstream(self, node_name: str, port: str = "") -> None:
        """COMPOSITE_CHILD + VISIBLE + CONNECTED → disconnect：双写立即清除。"""
        comp_id = self._mgr._membership_sms[node_name].comp_id
        node_cfg_path = self._get_node_config_path(node_name)
        port_name = port or self._mgr._connection_sms[node_name].upstream_port
        # 1. 清除子节点 listen_upper_file
        self._route_cache.clear_listen_upper_file(node_cfg_path)
        # 2. 清除复合节点路由
        self._route_cache.clear_composite_routing(comp_id, port_name)
        # 3. 清 ConnectionSM 附属
        self._mgr._connection_sms[node_name].upstream_port = ""
        self._mgr._connection_sms[node_name].upstream_node_name = ""
        self._mgr._connection_sms[node_name].upstream_output_path = ""
```

class RouteCache:
    """配置写盘内存缓冲，批量操作 → 一次性原子落盘。"""

    def __init__(self, cache: RouteCache, owner: str):
        self._snapshot = cache.snapshot(owner)   # 回滚快照
    def commit(self) -> None: ...               # 标记事务 OK
    def rollback(self) -> None:
        """中途异常 → 整体恢复快照，保证一致性。"""

### 6.2 非法状态组合校验（is_valid_combined_state）

> **评审修订5**：提供合法性校验工具，快速识别非法组合。

```python
ILLEGAL_COMBINATIONS = [
    # 独立节点不可见
    lambda s: (s.membership == STANDALONE and s.visibility != VISIBLE,
               "STANDALONE node must always VISIBLE"),
    # COMPOSITE_CHILD + 运行中不可 decompress
    lambda s: (s.membership == COMPOSITE_CHILD
               and s.runtime in (STARTING, RUNNING, STOPPING)
               and s.last_event == "decompress_from_composite",
               "runtime child cannot decompress"),
    # COMPOSITE 运行中不可增删子节点/切入口
    lambda s: (s.membership == COMPOSITE
               and s.runtime in (STARTING, RUNNING, STOPPING)
               and s.last_event in ("add_child_node", "remove_child_node", "switch_entry_node"),
               "running composite cannot modify structure"),
    # CONNECTED → 必须有合法的 upstream_path（调试用）
    lambda s: (s.connection.upstream == CONNECTED
               and not s.connection.upstream_output_path,
               "CONNECTED but upstream_path empty"),
]

def is_valid_combined_state(state: dict) -> tuple[bool, str]:
    for rule in ILLEGAL_COMBINATIONS:
        hit, reason = rule(state)
        if hit:
            return False, reason
    return True, ""
```

## 十一、测试方案（评审修订版）

### 11.1 单元测试

| 类别 | 用例 | 验证点 |
|------|------|--------|
| 状态机合法转换 | 每类事件 × 合法前置状态 | 返回 True；get_state 返回目标状态 |
| **非法状态用例**（评审新增） | 连续 expand / start 中切入口 / 运行中 compress | 返回 False；audit_log 记录 illegal；状态未变更 |
| **事务回滚用例**（评审新增） | batch expand 到第 3 个子节点时注入 IO 异常 | 未更新的文件未写入；已更新的内存缓存回滚；整体状态一致 |
| 并发竞态 | 2 线程同时 handle_event 同一节点 start | 一个成功、一个失败（锁串行化），不崩溃 |
| 防抖去重 | 10ms 内连续触发两次 expand | 第二次被 debounced 丢弃，静默不报错 |
| 连接状态同步 | standalone/child/composite 各场景 disconnect | listen_upper_file + _port_routing 立即清除，无 300ms 延迟残留 |

### 11.2 集成测试（UI + 配置）

| 场景 | 步骤 | 预期 |
|------|------|------|
| 折叠态连复合 → 展开 → 子节点有配置 | 折叠复合 → 外部连复合 → 展开 | UI：外部→子节点连线可见；配置：子节点 listen_upper_file 有值 |
| 展开态连子节点 → 折叠 → 复合有路由 | 展开 → 外部连子 → 折叠 | UI：外部→复合连线可见；配置：_port_routing 有值 |
| 删除连线 → 快速连新节点 → 无残留 | 连节点A → 删除 → 立即连节点B | 配置：A 的路由清除，B 正确写入；无竞态残留 |
| 折叠→展开→折叠 不丢线 | 折叠态有连接 → 展开 → 折叠 | UI：前后连线一致；展开时独占检测无"已连接"误判 |
| 解耦保留连接 | 子节点有外部连 → 解耦 | STANDALONE 后 listen_upper_file 保留有效，连线仍显示 |
| 运行中禁止结构变更 | start 复合 → 切换入口/增删子 | 菜单禁用 + handle_event 返回 False；提示"运行中不可操作" |
| **故障注入一致性**（评审新增） | batch expand 中途 kill 程序 → 重启 → validate_all | 重启后 validate_all 无非法组合；重新加载状态可恢复 |

- 500 子节点复合节点：expand 全量时间 < 500ms（事务批量 flush 一次 IO）
- 1000 子节点复合节点：collapse 全量时间 < 500ms
- 连续 100 次 create/remove_edge 独立节点：配置写盘无延迟 > 200ms 抖动

## 十二、风险与缓解（评审修订版）

| 风险 | 等级 | 缓解措施 |
|------|------|----------|
| Manager 与 ActionService 边界再次混杂 | 中 | 代码评审：Manager 中禁止任何 open/json.dump/子节点遍历循环 |
| 矩阵行遗漏导致组合非法 | 中 | `transition_table` 用枚举穷尽校验；单元测试遍历每个 (membership × visibility × connection) × 每事件 |
| 批量事务异常后状态残留 | 高 | RouteCache 快照回滚 + 异常后自动 `validate_all` 告警 |
| 调试日志量过大影响性能 | 低 | audit_log 环形缓冲（默认上限 5000 条）；生产可设置关闭 |
| 并发锁死锁 | 低 | 锁仅作用于单节点；Manager 内部禁止跨节点嵌套加锁 |
| 节点注销后残留引用 | 中 | unregister 完整清理 4 个维度 SM + 锁 + 防抖表 + 路由缓存；单元测试专门验证注销后 dump_all 无残留 |

## 十三、方案优势总结（评审修订版）

| 维度 | 说明 |
|------|------|
| **正交解耦彻底** | 4 个平级独立子状态机，新增维度只加 SM 不改核心 |
| **状态与副作用分离** | Manager 纯状态、ActionService 纯副作用，各自易测试 |
| **数据驱动事件矩阵** | TRANSITION_TABLE 配置化，新增事件零侵入 Manager |
| **并发安全** | 单节点锁串行化 + 防抖去重 + 注销兜底，无竞态崩溃 |
| **批量事务一致性** | RouteCache + Transaction 原子落盘 + 回滚，expand/collapse 中途报错无半更新 |
| **工程化完备** | is_valid_combined_state / dump_all / audit_log 三件套，线上可观测可诊断 |
| **落地友好** | 五阶段实施 + 并行双写灰度 + 先复合后独立的切换策略，风险极低 |
| **目录分层清晰** | orthogonal/ 子包存放纯 SM，支撑组件与复用组件同级，导入依赖有严格规则，无循环 import
