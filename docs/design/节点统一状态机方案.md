# 节点统一状态机方案

## 一、问题分析

### 1.1 现有问题

当前节点系统存在多维度的状态管理问题：

| 问题分类 | 具体问题 | 影响范围 |
|----------|----------|----------|
| **成员状态** | 普通节点 vs 复合节点子节点，状态切换时配置同步不一致 | 所有节点 |
| **运行状态** | 节点运行/停止状态分散在多个地方管理 | 所有节点 |
| **连接状态** | 上游连接状态与配置文件不同步，删除连接后配置残留 | 所有节点 |
| **复合状态** | 复合节点展开/折叠时，子节点配置和连线状态管理混乱 | 复合节点子节点 |

### 1.2 现有状态机分析

| 状态机 | 文件 | 覆盖维度 | 缺失维度 |
|--------|------|----------|----------|
| `NodeRuntimeSM` | `node_runtime.py` | 运行时（启动/停止/崩溃） | 成员状态、连接状态、复合状态 |
| `CompositeLifecycleSM` | `composite_lifecycle.py` | 复合节点生命周期 | 普通节点状态、连接状态 |
| `EdgeInteractionSM` | `edge_interaction.py` | 边交互 | 节点状态 |

**结论**：现有状态机只覆盖了单一维度，缺乏跨维度的统一状态管理。

---

## 二、方案设计

### 2.1 核心思路：多维度组合状态机

采用**维度分离**的设计思想，将节点状态拆分为多个独立维度，每个维度由独立的子状态机管理，再通过统一管理器协调。

```
┌───────────────────────────────────────────────────────────────┐
│                    NodeStateManager（统一管理器）               │
│  ┌──────────────┐  ┌──────────────┐  ┌──────────────────────┐ │
│  │ 成员状态机   │  │ 连接状态机   │  │ 运行状态机（复用）   │ │
│  │ MembershipSM │  │ConnectionSM  │  │ NodeRuntimeSM        │ │
│  └──────────────┘  └──────────────┘  └──────────────────────┘ │
│  ┌──────────────────────────────────────────────────────────┐ │
│  │            复合状态维度（仅子节点适用）                     │ │
│  │  COMPOSITE_COLLAPSED / COMPOSITE_EXPANDED                │ │
│  └──────────────────────────────────────────────────────────┘ │
└───────────────────────────────────────────────────────────────┘
```

### 2.2 状态维度定义

#### 维度一：成员状态（Membership State）

描述节点在项目中的角色。

| 状态 | 说明 | 适用范围 |
|------|------|----------|
| `STANDALONE` | 独立节点（非复合节点子节点） | 普通节点、复合节点本身 |
| `COMPOSITE_CHILD` | 复合节点子节点 | 复合节点内部的节点 |

**状态转换**：

```
STANDALONE ──add_to_composite──→ COMPOSITE_CHILD
         ←──remove_from_composite───
```

#### 维度二：复合可见性状态（Composite Visibility State）

仅当成员状态为 `COMPOSITE_CHILD` 时有效。

| 状态 | 说明 |
|------|------|
| `COLLAPSED` | 复合节点折叠中，子节点隐藏 |
| `EXPANDED` | 复合节点展开中，子节点可见 |

**状态转换**：

```
COLLAPSED ──expand──→ EXPANDED
         ←──collapse───
```

#### 维度三：运行状态（Runtime State）

复用现有的 `NodeRuntimeSM`。

| 状态 | 说明 |
|------|------|
| `STOPPED` | 已停止 |
| `STARTING` | 正在启动 |
| `RUNNING` | 运行中 |
| `IDLE` | 运行中空闲 |
| `STOPPING` | 正在停止 |
| `CRASHED` | 异常终止 |

#### 维度四：上游连接状态（Upstream Connection State）

描述节点是否有上游输入连接。

| 状态 | 说明 |
|------|------|
| `DISCONNECTED` | 无上游连接 |
| `CONNECTED` | 有上游连接 |

**状态转换**：

```
DISCONNECTED ──connect──→ CONNECTED
           ←──disconnect───
```

## 三、状态矩阵与合法性校验

### 3.1 完整状态组合

每个节点的完整状态是四个维度的组合：

```
完整状态 = (成员状态, 复合可见性, 运行状态, 连接状态)
```

**示例**：

| 完整状态组合 | 说明 |
|--------------|------|
| `(STANDALONE, N/A, RUNNING, CONNECTED)` | 独立运行中的普通节点，有上游连接 |
| `(COMPOSITE_CHILD, COLLAPSED, STOPPED, CONNECTED)` | 折叠中的复合节点子节点，已停止，有上游连接 |
| `(COMPOSITE_CHILD, EXPANDED, RUNNING, DISCONNECTED)` | 展开中的复合节点子节点，运行中，无上游连接 |

### 3.2 合法性约束

| 约束条件 | 说明 |
|----------|------|
| 复合可见性仅在 `COMPOSITE_CHILD` 时有效 | 独立节点无复合可见性状态 |
| 运行状态 `RUNNING/IDLE` 时不能删除节点 | 运行中节点禁止破坏性操作 |
| 复合可见性 `EXPANDED` 时，子节点配置可直接修改 | 折叠时配置由复合节点代理 |
| 连接状态 `CONNECTED` 时，配置中必须有对应 `listen_upper_file` | 状态与配置一致 |

## 四、事件与动作映射

### 4.1 事件定义

| 事件 | 触发维度 | 影响维度 |
|------|----------|----------|
| `add_to_composite` | 用户操作 | 成员状态：STANDALONE → COMPOSITE_CHILD |
| `remove_from_composite` | 用户操作 | 成员状态：COMPOSITE_CHILD → STANDALONE |
| `expand` | 用户操作 | 复合可见性：COLLAPSED → EXPANDED |
| `collapse` | 用户操作 | 复合可见性：EXPANDED → COLLAPSED |
| `start` | 用户操作/系统 | 运行状态转换 |
| `stop` | 用户操作/系统 | 运行状态转换 |
| `connect_upstream` | 用户创建连线 | 连接状态：DISCONNECTED → CONNECTED |
| `disconnect_upstream` | 用户删除连线 | 连接状态：CONNECTED → DISCONNECTED |

### 4.2 动作定义

| 动作 | 触发时机 | 具体操作 |
|------|----------|----------|
| `sync_config_to_child` | expand 时 | 从复合节点 `_port_routing` 同步到子节点 `listen_upper_file` |
| `sync_config_to_composite` | collapse 时 | 从子节点 `listen_upper_file` 同步到复合节点 `_port_routing` |
| `clear_child_config` | collapse 时 | 清除子节点的外部引用（`listen_upper_file` 等） |
| `update_listen_upper_file` | connect_upstream 时 | 写入/更新节点的 `listen_upper_file` |
| `clear_listen_upper_file` | disconnect_upstream 时 | 清除节点的 `listen_upper_file` |
| `update_composite_routing` | connect_upstream/disconnect_upstream 时 | 更新复合节点的 `_port_routing` |
| `immediate_sync_config` | disconnect_upstream 时 | 立即同步到配置文件（消除延迟写入竞态） |

## 五、核心组件设计

### 5.1 MembershipSM（成员状态机）

**文件路径**：`ui/core/state/node_membership.py`

**状态枚举**：

```python
class NodeMembershipState(str, Enum):
    STANDALONE = "standalone"          # 独立节点
    COMPOSITE_CHILD = "composite_child"  # 复合节点子节点
```

**附属数据**：

| 字段 | 类型 | 说明 |
|------|------|------|
| `comp_id` | `str` | 所属复合节点 ID（仅 COMPOSITE_CHILD 时有效） |
| `composite_visibility` | `str` | 复合可见性：`collapsed` / `expanded` |

### 5.2 ConnectionSM（连接状态机）

**文件路径**：`ui/core/state/node_connection.py`

**状态枚举**：

```python
class NodeConnectionState(str, Enum):
    DISCONNECTED = "disconnected"    # 无上游连接
    CONNECTED = "connected"          # 有上游连接
```

**附属数据**：

| 字段 | 类型 | 说明 |
|------|------|------|
| `upstream_port` | `str` | 上游连接的端口名 |
| `upstream_node` | `str` | 上游节点名称 |
| `upstream_path` | `str` | 上游 output.json 路径 |

### 5.3 NodeStateManager（统一状态管理器）

**文件路径**：`ui/core/state/node_state_manager.py`

**职责**：协调各维度状态机，统一处理事件和动作。

**接口设计**：

| 方法 | 参数 | 返回值 | 说明 |
|------|------|--------|------|
| `register_node` | `node_name: str`, `is_composite_child: bool` | - | 注册节点状态机 |
| `unregister_node` | `node_name: str` | - | 注销节点状态机 |
| `handle_event` | `node_name: str`, `event: str`, `**kwargs` | `bool` | 触发节点事件 |
| `get_full_state` | `node_name: str` | `dict` | 获取节点完整状态（四维度组合） |
| `is_allowed` | `node_name: str`, `action: str` | `bool` | 检查某操作是否允许（基于当前状态） |
| `get_runtime_sm` | `node_name: str` | `NodeRuntimeSM` | 获取运行状态机（复用现有） |

### 5.4 与现有状态机的集成方式

```
NodeStateManager
    ├── {node_name: MembershipSM}       — 新增
    ├── {node_name: ConnectionSM}       — 新增
    ├── {node_name: NodeRuntimeSM}      — 复用现有
    └── {comp_id: CompositeLifecycleSM} — 复用现有
```

**复用策略**：
- `NodeRuntimeSM`：直接复用，通过 `NodeStateManager.get_runtime_sm()` 访问
- `CompositeLifecycleSM`：直接复用，作用于复合节点本身
- `EdgeInteractionSM`：不纳入，保持边交互独立

## 六、配置同步规则

### 6.1 状态变化时的配置同步矩阵

| 起始状态 | 事件 | 目标状态 | 配置同步动作 |
|----------|------|----------|--------------|
| STANDALONE, N/A, *, * | add_to_composite | COMPOSITE_CHILD, COLLAPSED, *, * | 暂不改变配置 |
| COMPOSITE_CHILD, COLLAPSED, *, * | expand | COMPOSITE_CHILD, EXPANDED, *, * | `sync_config_to_child` |
| COMPOSITE_CHILD, EXPANDED, *, * | collapse | COMPOSITE_CHILD, COLLAPSED, *, * | `sync_config_to_composite` + `clear_child_config` |
| COMPOSITE_CHILD, COLLAPSED, *, * | remove_from_composite | STANDALONE, N/A, *, * | 从 `_port_routing` 恢复配置到 `listen_upper_file` |
| COMPOSITE_CHILD, EXPANDED, *, DISCONNECTED | connect_upstream | COMPOSITE_CHILD, EXPANDED, *, CONNECTED | `update_listen_upper_file` |
| COMPOSITE_CHILD, EXPANDED, *, CONNECTED | disconnect_upstream | COMPOSITE_CHILD, EXPANDED, *, DISCONNECTED | `clear_listen_upper_file` + `update_composite_routing` + `immediate_sync_config` |
| COMPOSITE_CHILD, COLLAPSED, *, DISCONNECTED | connect_upstream | COMPOSITE_CHILD, COLLAPSED, *, CONNECTED | `update_composite_routing` |
| COMPOSITE_CHILD, COLLAPSED, *, CONNECTED | disconnect_upstream | COMPOSITE_CHILD, COLLAPSED, *, DISCONNECTED | `update_composite_routing` + `immediate_sync_config` |
| STANDALONE, N/A, *, DISCONNECTED | connect_upstream | STANDALONE, N/A, *, CONNECTED | `update_listen_upper_file` |
| STANDALONE, N/A, *, CONNECTED | disconnect_upstream | STANDALONE, N/A, *, DISCONNECTED | `clear_listen_upper_file` |

### 6.2 关键同步动作详解

#### 动作1：sync_config_to_child（expand 时）

```python
def sync_config_to_child(self, node_name: str, comp_id: str):
    """从复合节点 _port_routing 同步到子节点 listen_upper_file"""
    routing = composite_manager._get_port_routing(comp_id)
    port_to_internal = self._build_port_to_internal(comp_id)
    child_config_path = get_config_path_for_node(node_name)
    
    for port_name, route in routing.get("input", {}).items():
        internal_node = port_to_internal.get(port_name)
        if internal_node == node_name:
            source_path = route.get("source_output_path", "")
            if source_path:
                write_listen_upper_file(child_config_path, source_path)
                connection_sm = self._connection_sms[node_name]
                connection_sm.upstream_node = extract_node_from_path(source_path)
                connection_sm.upstream_path = source_path
                connection_sm.handle("connect")  # 切换到 CONNECTED
```

#### 动作2：sync_config_to_composite（collapse 时）

```python
def sync_config_to_composite(self, node_name: str, comp_id: str):
    """从子节点 listen_upper_file 同步到复合节点 _port_routing"""
    child_config_path = get_config_path_for_node(node_name)
    listen = read_listen_upper_file(child_config_path)
    
    if listen:
        port_name = self._get_port_name_for_child(node_name, comp_id)
        if port_name:
            composite_manager.set_input_routing(comp_id, port_name, listen)
            composite_manager._sync_routing_to_config(comp_id)  # 立即同步
```

#### 动作3：disconnect_upstream + immediate_sync_config

```python
def on_disconnect_upstream(self, node_name: str):
    """断开上游连接时的处理"""
    membership = self.get_membership(node_name)
    full_state = self.get_full_state(node_name)
    
    # 清除节点配置
    self._clear_listen_upper_file(node_name)
    
    # 如果是复合节点子节点，同时清除复合节点路由
    if membership == NodeMembershipState.COMPOSITE_CHILD:
        comp_id = self._membership_sms[node_name].comp_id
        port_name = self._get_port_name_for_child(node_name, comp_id)
        if port_name:
            composite_manager.clear_input_routing(comp_id, port_name)
            composite_manager._sync_routing_to_config(comp_id)  # 立即同步，消除延迟竞态
    
    # 切换连接状态
    self._connection_sms[node_name].handle("disconnect")
```

## 十一、风险评估与缓解

| 风险 | 等级 | 缓解措施 |
|------|------|----------|
| 多维度状态组合爆炸 | 中 | 维度独立管理，仅在需要时校验组合合法性，不枚举所有组合 |
| 与现有逻辑冲突 | 高 | 采用渐进式替换：先在状态机中处理，确认正确后再移除旧逻辑 |
| 事件触发遗漏 | 中 | 在关键入口（create_edge/remove_edge/expand/collapse）统一触发，不分散调用 |
| 性能影响 | 低 | 状态机本身为内存操作，可忽略；配置同步按需触发，不频繁写盘 |
| 向后兼容性 | 高 | 状态机不强制替换现有逻辑，先并行运行，确认无误后再切换 |

## 十二、方案优势

| 维度 | 说明 |
|------|------|
| **覆盖全面** | 涵盖成员状态、复合可见性、运行状态、连接状态四个维度 |
| **维度独立** | 各维度状态机独立，互不影响，可单独测试和演进 |
| **复用优先** | 运行状态机直接复用现有 `NodeRuntimeSM`，不重复开发 |
| **非侵入式** | 状态管理器独立于 NodeItem，不嵌入业务对象 |
| **统一入口** | 所有状态变化通过 `NodeStateManager.handle_event()` 触发，可追溯可审计 |
| **动作集中** | 配置同步动作集中定义在状态机中，不分散在多个业务函数 |
| **可扩展性** | 新增状态维度（如下游连接状态、错误状态等）只需添加子状态机 |
