# 节点统一状态机方案（完整版）

## 一、节点类型与问题分析

### 1.1 三种节点类型

当前系统存在三种节点类型，各有不同的行为特征和状态维度：

| 节点类型 | 类名 | 说明 | 配置文件 | 现有状态机 |
|----------|------|------|----------|------------|
| **独立节点** | `NodeItem` | 普通节点，不属于任何复合节点 | `node_config.json` | `NodeRuntimeSM` |
| **复合节点子节点** | `NodeItem` | 属于某个复合节点内部的子节点 | `node_config.json` | `NodeRuntimeSM` |
| **复合节点本身** | `CompositeNodeItem` | 复合节点作为整体存在于画布上 | `node_clusters.json` / `composite.json` | `CompositeLifecycleSM` |

### 1.2 三种节点的状态维度差异

| 状态维度 | 独立节点 | 复合节点子节点 | 复合节点本身 |
|----------|----------|----------------|--------------|
| 成员角色 | ✅ STANDALONE | ✅ COMPOSITE_CHILD | ✅ COMPOSITE |
| 可见性状态 | ✅（始终可见） | ✅ COLLAPSED / EXPANDED | ✅ COLLAPSED / EXPANDED |
| 运行状态 | ✅ NodeRuntimeSM | ✅ NodeRuntimeSM | ✅ CompositeLifecycleSM |
| 上游连接状态 | ✅（直接 listen_upper_file） | ✅（子节点 listen_upper_file） | ✅（通过 _port_routing 代理） |
| 下游连接状态 | ✅ | ✅ | ✅ |
| 内部子节点管理 | ❌ | ❌ | ✅（子节点增删、入口切换） |

### 1.3 现有问题（按节点类型分）

#### 独立节点问题

| 问题 | 描述 |
|------|------|
| 删除连线配置残留 | 删除连线后 `listen_upper_file` 未及时清除，后续连接覆盖但不删除 |
| 连接状态与配置不同步 | 连接存在但配置中无记录，或配置中有记录但连线已删除 |

#### 复合节点子节点问题

| 问题 | 描述 |
|------|------|
| 展开后无外部连接 | 折叠状态连接复合节点，展开后子节点 `listen_upper_file` 为空 |
| 折叠后复合配置丢失 | 展开状态连接子节点，折叠后复合节点 `_port_routing` 未写入 |
| 折叠丢失线条 / 展开误判已连接 | 连线状态在折叠/展开时不一致 |
| 删除连线复合配置未更新 | 折叠状态删除连线，`_port_routing` 未清除（延迟写入竞态） |

#### 复合节点本身问题

| 问题 | 描述 |
|------|------|
| 展开/折叠状态独立管理 | 复合节点的展开折叠与子节点可见性状态未统一协调 |
| 子节点管理无状态约束 | 运行中仍可增删子节点、切换入口节点，可能导致不一致 |

## 二、方案设计

### 2.1 核心思路：节点类型分层 + 多维度组合状态机

```
┌───────────────────────────────────────────────────────────────────────┐
│                        NodeStateManager（统一管理器）                   │
│                                                                       │
│  ┌─────────────────────────────────────────────────────────────────┐  │
│  │ 第一层：成员角色状态机（MembershipSM）                            │  │
│  │   STANDALONE / COMPOSITE_CHILD / COMPOSITE                      │  │
│  └─────────────────────────────────────────────────────────────────┘  │
│                                                                       │
│  ┌──────────────────┐  ┌──────────────────┐  ┌────────────────────┐  │
│  │ 可见性状态机     │  │ 连接状态机       │  │ 运行状态机（复用） │  │
│  │ VisibilitySM     │  │ ConnectionSM     │  │ NodeRuntimeSM /     │  │
│  │ （按节点类型     │  │ （上下游分别）   │  │ CompositeLifecycleSM│  │
│  │   行为不同）     │  │                  │  │                    │  │
│  └──────────────────┘  └──────────────────┘  └────────────────────┘  │
│                                                                       │
│  ┌─────────────────────────────────────────────────────────────────┐  │
│  │ 复合节点专属维度（仅 COMPOSITE 类型有效）                         │  │
│  │   - 子节点列表管理（增删）                                        │  │
│  │   - 入口节点切换                                                 │  │
│  │   - 内部连线状态（子节点之间的连接）                               │  │
│  └─────────────────────────────────────────────────────────────────┘  │
└───────────────────────────────────────────────────────────────────────┘
```

### 2.2 第一层：成员角色状态（Membership）

描述节点在项目中的**角色类型**，三种互斥值：

| 状态 | 说明 | 适用对象 |
|------|------|----------|
| `STANDALONE` | 独立节点（普通节点） | 独立的 `NodeItem` |
| `COMPOSITE_CHILD` | 复合节点内部子节点 | 复合节点内的 `NodeItem` |
| `COMPOSITE` | 复合节点（作为整体） | `CompositeNodeItem` |

**状态转换**：

```
STANDALONE ──compress_into_composite──→ COMPOSITE_CHILD
         ←──decompress_from_composite───

（COMPOSITE 由创建/删除操作直接产生/销毁，无动态转换）
```

**附属数据**：

| 字段 | 适用类型 | 说明 |
|------|----------|------|
| `comp_id` | COMPOSITE_CHILD, COMPOSITE | 复合节点 ID |
| `child_node_names` | COMPOSITE | 子节点名称列表 |
| `entry_node` | COMPOSITE | 入口节点名称 |

### 2.3 第二层：可见性状态（Visibility）

描述节点在画布上的**显示状态**。

| 状态 | 独立节点（STANDALONE） | 复合节点子节点（COMPOSITE_CHILD） | 复合节点本身（COMPOSITE） |
|------|------------------------|-----------------------------------|---------------------------|
| `VISIBLE` | ✅ 默认且唯一值 | ❌ 复合节点展开时 | ✅ 始终可见（展开模式） |
| `HIDDEN_COLLAPSED` | ❌ | ✅ 复合节点折叠时（子节点隐藏） | ✅ 折叠模式（子节点隐藏） |

**注意**：三种节点类型的可见性状态含义不同：
- 独立节点：始终 `VISIBLE`，无转换
- 复合节点子节点：`VISIBLE` ↔ `HIDDEN_COLLAPSED`，跟随父复合节点的 expand/collapse
- 复合节点本身：始终 `VISIBLE`（折叠不影响复合节点本身可见），但有自己的折叠/展开模式状态作为子属性

### 2.4 第三层：连接状态（Connection）

描述节点的**上游和下游连接**，分别管理（一个节点可能同时有上游和下游）。

**上游连接状态（Upstream）**：

| 状态 | 说明 |
|------|------|
| `DISCONNECTED` | 无上游输入连接 |
| `CONNECTED` | 有上游输入连接 |

**下游连接状态（Downstream）**：

| 状态 | 说明 |
|------|------|
| `NO_OUTPUTS` | 无下游输出连接 |
| `HAS_OUTPUTS` | 有下游输出连接 |

**连接状态附属数据**：

| 字段 | 类型 | 说明 |
|------|------|------|
| `upstream_port` | `str` | 上游连接的输入端口名（CONNECTED 时） |
| `upstream_node_name` | `str` | 上游节点名称（CONNECTED 时） |
| `upstream_output_path` | `str` | 上游 output.json 路径（CONNECTED 时） |
| `downstream_edges` | `int` | 下游连接数量（HAS_OUTPUTS 时） |

**对于三种节点类型的差异**：

| 差异点 | STANDALONE | COMPOSITE_CHILD | COMPOSITE |
|--------|-----------|-----------------|-----------|
| 上游配置写入位置 | 自身 `listen_upper_file` | 自身 `listen_upper_file`（展开时） / 父复合的 `_port_routing`（折叠时） | 自身 `_port_routing` |
| 上游配置读取位置 | 自身配置 | 自身配置 + 父复合路由 | 自身 `_port_routing` |
| 下游配置 | 直接连线（无配置写入） | 直接连线（无配置写入） | 子节点输出端口代理（`_port_routing` output 项） |

### 2.5 第四层：运行状态（Runtime）

复用现有状态机，按节点类型选择。

| 节点类型 | 复用的状态机 | 状态集 |
|----------|-------------|--------|
| STANDALONE | `NodeRuntimeSM` | STOPPED / STARTING / RUNNING / IDLE / STOPPING / CRASHED |
| COMPOSITE_CHILD | `NodeRuntimeSM` | STOPPED / STARTING / RUNNING / IDLE / STOPPING / CRASHED |
| COMPOSITE | `CompositeLifecycleSM` | CREATED / STARTING / RUNNING / STOPPING / STOPPED / CRASHED / REMOVING / REMOVED |

### 2.6 完整状态组合表示

每个节点的完整状态是一个五元组：

```
完整状态 = (
    成员角色: STANDALONE | COMPOSITE_CHILD | COMPOSITE,
    可见性:   VISIBLE | HIDDEN_COLLAPSED,
    上游连接: DISCONNECTED | CONNECTED,
    下游连接: NO_OUTPUTS | HAS_OUTPUTS,
    运行状态: （按节点类型对应）
)
```

## 三、状态转换事件矩阵

### 3.1 事件定义

| 事件 | 说明 | 可触发的节点类型 |
|------|------|-----------------|
| `compress_into_composite` | 节点被压入（成为复合节点子节点） | STANDALONE → COMPOSITE_CHILD |
| `decompress_from_composite` | 节点被解耦（从复合节点弹出） | COMPOSITE_CHILD → STANDALONE |
| `expand` | 展开复合节点 | COMPOSITE + COMPOSITE_CHILD（子节点切换可见） |
| `collapse` | 折叠复合节点 | COMPOSITE + COMPOSITE_CHILD（子节点切换隐藏） |
| `create_composite` | 创建新的复合节点 | 产生 COMPOSITE 类型节点 |
| `delete_composite` | 删除复合节点（解耦所有子节点后销毁） | COMPOSITE 销毁 |
| `add_child_node` | 向复合节点追加子节点 | COMPOSITE |
| `remove_child_node` | 从复合节点移除子节点 | COMPOSITE |
| `switch_entry_node` | 切换复合节点入口 | COMPOSITE |
| `connect_upstream` | 创建上游输入连线 | 所有类型 |
| `disconnect_upstream` | 删除上游输入连线 | 所有类型 |
| `connect_downstream` | 创建下游输出连线 | 所有类型 |
| `disconnect_downstream` | 删除下游输出连线 | 所有类型 |
| `start` | 启动节点/复合节点 | 所有类型 |
| `stop` | 停止节点/复合节点 | 所有类型 |

### 3.2 状态转换时的配置同步动作（核心）

以下是三种节点类型在关键事件时的配置同步规则，解决当前的 Bug：

#### 3.2.1 STANDALONE（独立节点）的配置同步

| 起始状态 | 事件 | 动作（配置同步） |
|----------|------|-----------------|
| 任意 | `connect_upstream` | 1. 写入 `listen_upper_file` = 上游 output.json 路径<br>2. 切换上游连接状态 → CONNECTED |
| (CONNECTED) | `disconnect_upstream` | 1. **立即**清除 `listen_upper_file`<br>2. 切换上游连接状态 → DISCONNECTED<br>（不使用延迟写入，消除竞态） |
| 任意 | `connect_downstream` | 下游计数 +1；从 0→1 时切换 → HAS_OUTPUTS |
| (HAS_OUTPUTS) | `disconnect_downstream` | 下游计数 -1；从 1→0 时切换 → NO_OUTPUTS |
| (RUNNING/IDLE) | `compress_into_composite` | ❌ 拒绝；运行中节点不能压入复合 |

#### 3.2.2 COMPOSITE_CHILD（复合节点子节点）的配置同步

| 起始状态 | 事件 | 动作（配置同步） |
|----------|------|-----------------|
| (VISIBLE, DISCONNECTED) | `connect_upstream` | 1. 写入子节点 `listen_upper_file` = 上游路径<br>2. 同步写入父复合的 `_port_routing`（按端口映射）<br>3. **立即** `_sync_routing_to_config(comp_id)`<br>4. 上游状态 → CONNECTED |
| (VISIBLE, CONNECTED) | `disconnect_upstream` | 1. **立即**清除子节点 `listen_upper_file`<br>2. **立即**清除父复合对应端口的 `_port_routing`<br>3. **立即** `_sync_routing_to_config(comp_id)`<br>4. 上游状态 → DISCONNECTED |
| (HIDDEN_COLLAPSED, DISCONNECTED) | `connect_upstream` | 1. 仅写入父复合 `_port_routing`<br>2. **立即** `_sync_routing_to_config(comp_id)`<br>3. 上游状态 → CONNECTED<br>（子节点 listen_upper_file 暂不写，expand 时同步） |
| (HIDDEN_COLLAPSED, CONNECTED) | `disconnect_upstream` | 1. **立即**清除父复合对应端口的 `_port_routing`<br>2. **立即** `_sync_routing_to_config(comp_id)`<br>3. 上游状态 → DISCONNECTED |
| (HIDDEN_COLLAPSED, CONNECTED) | `expand` | 1. 从父复合 `_port_routing` 读取路由<br>2. 按 `port_to_internal` 映射找到本节点<br>3. 写入子节点 `listen_upper_file` = 对应路径<br>4. 可见性 → VISIBLE |
| (VISIBLE, CONNECTED) | `collapse` | 1. 从子节点 `listen_upper_file` 读取路径<br>2. 若父复合 `_port_routing` 无对应记录，补写<br>3. **立即** `_sync_routing_to_config(comp_id)`<br>4. **清除**子节点 `listen_upper_file`<br>5. 可见性 → HIDDEN_COLLAPSED |
| (VISIBLE, DISCONNECTED) | `collapse` | 1. 可见性 → HIDDEN_COLLAPSED<br>（无需配置同步） |
| (HIDDEN_COLLAPSED, DISCONNECTED) | `expand` | 1. 可见性 → VISIBLE<br>（无需配置同步） |
| (CONNECTED / RUNNING) | `decompress_from_composite` | 1. 先从父复合 `_port_routing` 读取本节点对应端口的路径<br>2. 若存在，写入 `listen_upper_file`（保留连接配置）<br>3. 从父复合 `_port_routing` 移除本节点端口项<br>4. 成员角色 → STANDALONE；可见性 → VISIBLE |

#### 3.2.3 COMPOSITE（复合节点本身）的配置同步

| 起始状态 | 事件 | 动作（配置同步） |
|----------|------|-----------------|
| 任意 | `connect_upstream` | 1. 写入复合 `_port_routing` input 项<br>2. **立即** `_sync_routing_to_config(comp_id)`<br>3. 同时向入口子节点触发状态检查（若 expand 中，同步子节点 listen_upper_file） |
| (CONNECTED) | `disconnect_upstream` | 1. **立即**清除对应端口的 `_port_routing` input 项<br>2. **立即** `_sync_routing_to_config(comp_id)`<br>3. 若 expand 中，同步清除子节点 listen_upper_file |
| 任意 | `connect_downstream` | 1. 写入 `_port_routing` output 项<br>2. **立即** `_sync_routing_to_config(comp_id)`<br>3. 下游 → HAS_OUTPUTS |
| (HAS_OUTPUTS) | `disconnect_downstream` | 1. **立即**清除对应端口的 `_port_routing` output 项<br>2. **立即** `_sync_routing_to_config(comp_id)`<br>3. 下游计数为 0 时 → NO_OUTPUTS |
| (HIDDEN_COLLAPSED) | `expand` | 1. 遍历 `_port_routing` input 项<br>2. 按 `port_to_internal` 映射分别写入各子节点的 `listen_upper_file`<br>3. 逐个触发各子节点的 `expand` 事件（可见性→VISIBLE）<br>4. 复合自身展开模式 → EXPANDED |
| (EXPANDED) | `collapse` | 1. 遍历各子节点，逐个触发 `collapse` 事件<br>   - 收集子节点 listen_upper_file<br>   - 补写/更新 `_port_routing` input 项<br>   - 清除子节点 listen_upper_file<br>2. **立即** `_sync_routing_to_config(comp_id)`<br>3. 子节点可见性 → HIDDEN_COLLAPSED<br>4. 复合自身折叠模式 → COLLAPSED |
| 任意 | `add_child_node` | 1. 更新 `child_node_names` 列表<br>2. 对子节点触发 `compress_into_composite` 事件 |
| 任意 | `remove_child_node` | 1. 对子节点触发 `decompress_from_composite` 事件<br>2. 更新 `child_node_names` 列表 |
| 任意 | `switch_entry_node` | 1. 更新 `entry_node`<br>2. 重新生成 `input_ports` 继承配置<br>3. 更新 `node_clusters.json` 的 entry + input_ports 字段<br>4. **立即**持久化 |
| (RUNNING / STARTING / STOPPING) | `add_child_node / remove_child_node / switch_entry_node` | ❌ 拒绝；运行中的复合节点不允许变更结构 |

## 四、连线状态管理（解决"折叠丢失线条，展开提示已连接"）

### 4.1 问题根因

折叠/展开时的连线变形操作与连接状态机不同步，导致：
1. 隐藏的连线仍存在于锚点的 edges 列表中 → 独占检测误判"已连接"
2. 变形后的连线未被正确标记 → 展开时无法还原

### 4.2 解决方案：由状态机统一驱动连线变形

**核心原则**：连线 UI 状态是连接状态机的投影，状态机是唯一真相源。

```
          事件触发（用户操作）
                 │
                 ▼
    NodeStateManager.handle_event()
                 │
        ┌────────┴────────┐
        ▼                 ▼
  连接状态机变更      配置同步动作
        │                 │
        └────────┬────────┘
                 ▼
       发出 state_changed 信号
                 │
                 ▼
  CanvasConnections 监听信号 → 执行连线变形
        （创建临时连线 / 隐藏 / 显示 / 清理）
```

**连线 UI 的具体规则**：

| 场景 | 由状态机驱动的动作 |
|------|-------------------|
| COMPOSITE_CHILD, collapse, CONNECTED | 1. 将外部→子节点的连线改为外部→复合节点的连线<br>2. 将原连线标记为 `_morphed_from_child`（保留用于还原）<br>3. **不**从锚点 edges 中移除原连线，只设 `hide()`<br>4. 独占检测时忽略 `isVisible()=False` 的连线 |
| COMPOSITE_CHILD, expand, CONNECTED | 1. 根据 `_morphed_from_child` 标记找到原连线<br>2. 恢复原连线 `show()`<br>3. 删除（或隐藏）外部→复合节点的代理连线<br>4. **清理**锚点 edges 列表中的隐藏连线，避免"已连接"误判 |
| connect_upstream / disconnect_upstream | 连线创建/删除动作由 CanvasConnections 自身完成后，**再**触发状态机事件确认状态（事件是结果，UI 操作是因） |

**独占检测修复（防"已连接"误判）**：
```python
# 在 create_edge 的独占检测中，过滤掉隐藏连线
existing = [e for e in anchor.edges if e.isVisible()]
if exclusive and any(... for e in existing):
    # 拒绝连接
```

## 五、核心组件设计

### 5.1 MembershipSM（成员角色状态机）

**文件**：`ui/core/state/node_membership.py`

```python
class NodeMembership(str, Enum):
    STANDALONE = "standalone"
    COMPOSITE_CHILD = "composite_child"
    COMPOSITE = "composite"

class MembershipSM(StateMachine):
    membership: NodeMembership
    comp_id: str = ""
    child_node_names: list[str] = []   # 仅 COMPOSITE
    entry_node: str = ""              # 仅 COMPOSITE
    visibility: str = "visible"       # visible / hidden_collapsed
```

### 5.2 ConnectionSM（连接状态机）

**文件**：`ui/core/state/node_connection.py`

```python
class UpstreamState(str, Enum):
    DISCONNECTED = "disconnected"
    CONNECTED = "connected"

class DownstreamState(str, Enum):
    NO_OUTPUTS = "no_outputs"
    HAS_OUTPUTS = "has_outputs"

class ConnectionSM:
    upstream_state: UpstreamState
    downstream_state: DownstreamState
    upstream_port: str = ""
    upstream_node_name: str = ""
    upstream_output_path: str = ""
    downstream_count: int = 0
```

### 5.3 NodeStateManager（统一管理器）

**文件**：`ui/core/state/node_state_manager.py`

**职责**：
1. 为每个 `node_name` 或 `comp_id` 注册/注销状态机集合
2. 统一 `handle_event(node_name, event, **kwargs)` 入口，在一个调用内完成：
   - 成员角色状态转换（含 guard 检查）
   - 可见性状态转换（含节点类型判断）
   - 连接状态转换
   - 触发对应配置同步动作
   - 运行状态机的事件转发（`start`/`stop` 转给对应 SM）
3. 发出 `state_changed(node_name, delta, full_state)` 信号

**核心方法**：

| 方法 | 说明 |
|------|------|
| `register_standalone(node_name)` | 注册独立节点 |
| `register_composite_child(node_name, comp_id)` | 注册复合子节点 |
| `register_composite(comp_id, child_names, entry)` | 注册复合节点 |
| `unregister(node_name_or_comp_id)` | 注销 |
| `handle_event(node_name, event, **kwargs)` | 统一事件入口 |
| `get_state(node_name)` | 获取完整状态五元组 |
| `is_allowed(node_name, action)` | 前置 guard 检查（运行中不可删除等） |

### 5.4 与现有状态机的复用关系

```
NodeStateManager（新增）
    │
    ├── {name: MembershipSM}     —— 新增（成员角色 + 可见性）
    ├── {name: ConnectionSM}     —— 新增（上下游连接）
    ├── {name: NodeRuntimeSM}    —— 复用（STANDALONE / COMPOSITE_CHILD 的运行状态）
    └── {comp_id: CompositeLifecycleSM} —— 复用（COMPOSITE 的运行状态）
```

## 十、风险与缓解

| 风险 | 等级 | 缓解 |
|------|------|------|
| 状态机逻辑复杂，矩阵行遗漏 | 高 | 配置同步矩阵写为数据驱动（dict 映射），枚举穷尽校验；单元测试覆盖每一行 |
| 与现有逻辑冲突导致双写不一致 | 高 | 并行双写 + 差异告警日志，不一致时以状态机为准并打 WARNING，待全部正确后移除旧逻辑 |
| create_edge 回滚复杂度 | 中 | 状态机 `handle_event` 返回 False 时，直接调用 `remove_edge` 回滚已创建的 UI 连线 |
| 性能影响 | 低 | 状态机为纯内存操作；配置同步即时写盘仅在 disconnect 时发生（比 300ms 延迟更快结束），connect 场景与旧逻辑无实质差异 |
