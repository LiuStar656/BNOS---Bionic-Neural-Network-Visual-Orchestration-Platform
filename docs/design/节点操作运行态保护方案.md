# 节点操作运行态保护方案

## 一、现状漏洞

| 操作 | 入口 | 检查运行状态？ | 风险 |
|------|------|:---:|------|
| **重命名** | 节点列表面板右键 | 否 | `os.rename` 在 Windows 上因进程占用文件夹而失败，可能导致 `nodes_data` 键已改但文件夹未改名 |
| **重命名** | 画布右键菜单 | 否 | 同上 |
| **重命名** | Dock 委托 | 否 | 同上 |
| **批量永久删除** | 节点列表面板 Ctrl+D / 菜单 | 否 | 静默强制终止进程，不告知用户有节点在运行 |
| **清空画布** | 切换项目时调用 `clear_canvas()` | 否 | 不停止任何进程，graphics item 被删但进程残留 |
| **从画布移除（原始方法）** | `remove_node_from_canvas()` | 否 | 纯画布操作，无确认无检查——但当前仅在 `_delete_node_async` 中调用（文件夹已删除），风险低 |
| **展开面板删除** | 展开面板 "删除" 按钮 | 否（入口层） | 委托给 `remove_node_with_cleanup` 后兜底，但入口层不拦截 |

### 已有保护的（无需修改）

| 操作 | 说明 |
|------|------|
| 从画布移除（单个+批量） | 会停止进程 + 确认弹窗 |
| 永久删除（单个） | 会停止进程 + 确认弹窗 |
| 复合节点右键菜单（展开/折叠/解耦） | `mgr.is_running()` 检查 |

## 二、修复方案

### 2.1 新增统一工具函数

在 `ui/core/node/node_process.py` 中新增：

```python
def check_node_not_running(node_name: str, nodes_data: dict) -> tuple[bool, str]:
    """检查节点是否处于运行态。
    
    Returns:
        (True, "")  — 安全，可以继续操作
        (False, msg) — 运行中，msg 为提示信息
    """
    node_info = nodes_data.get(node_name, {})
    status = node_info.get("status", "unknown")
    if status in ("running", "starting"):
        return False, f"节点「{node_name}」正在运行中，请先停止后再操作"
    return True, ""
```

### 2.2 重命名保护

**影响入口**：
- `ui/panels/node_list_panel.py` — `rename_node()`
- `ui/main_window/node.py` — `_rename_node_on_canvas_wrapper()`（画布右键委托）
- `ui/panels/node_list_dock.py` — `rename_node()`

**修复**：在弹窗之前（`rename_node()` 方法开头）加入运行状态检查：

```python
def rename_node(self, old_name: str):
    ok, msg = check_node_not_running(old_name, self.nodes_data)
    if not ok:
        self.show_toast(msg, "warning")
        return
    # ... 原有弹窗和重命名逻辑
```

**注意**：`nodes_data` 的访问方式在三个入口中不同：
- `node_list_panel` 有 `self.nodes_data`
- `node_list_dock` 通过 `self._find_panel()` 获取 panel，再拿 `nodes_data`
- `main_window/node.py` 通过 `self.nodes_data`

需要确保 `check_node_not_running` 能访问到正确的 `nodes_data`。

### 2.3 批量永久删除保护

**影响入口**：
- `ui/panels/node_list_panel.py` — `batch_delete_nodes()`

**修复**：在确认弹窗之前，筛查运行中的节点并告知用户：

```python
def batch_delete_nodes(self, node_names: list[str]):
    running = [n for n in node_names 
               if self.nodes_data.get(n, {}).get("status") in ("running", "starting")]
    
    if running:
        names = "、".join(running)
        reply = themed_message(
            self,
            "确认删除",
            f"以下 {len(running)} 个节点正在运行中：\n{names}\n\n"
            f"删除将同时停止这些节点。是否继续？",
            "warning2",
        )
        if reply != MSG_ACCEPT:
            return
    
    # ... 原有确认删除弹窗和删除逻辑
```

### 2.4 清空画布保护

**影响入口**：
- `ui/canvas/mixins/canvas_node_manager.py` — `clear_canvas()`
- 调用方：`ui/core/project/project_manager.py` 项目切换

**修复**：`clear_canvas()` 只处理画布 items，不涉及进程。但需要在项目切换调用 `clear_canvas()` **之前**确保所有节点已停止。当前项目切换的流程未知，需要确认。

如果项目切换时不需要额外保护（因为节点停止已在 project_manager 中处理），则此条可跳过。

### 2.5 移除 from canvas 原始方法（低风险）

`remove_node_from_canvas()` 当前仅被 `_delete_node_async()` 调用（此时文件夹已删、进程已停），无用户直接触发路径——**无需修改**。

## 三、复合节点运行时健康状态追踪（附加）

### 3.1 目标

让 BNOS 主进程感知复合节点内部子节点的运行状况，为后续的画布状态染色、告警通知提供数据基础。

### 3.2 数据格式

编排器在每次 DAG 执行后写入 `composite_nodes/<comp_id>/status.json`：

```json
{
  "comp_id": "composite_abc123",
  "updated_at": "2026-07-13T15:30:00",
  "last_run_id": "a1b2c3d4",
  "nodes": {
    "node_A": {
      "status": "ok",
      "duration_ms": 1234,
      "output_lines": 42,
      "last_ok_at": "2026-07-13T15:30:00"
    },
    "node_B": {
      "status": "fail",
      "error": "FAIL_RUN: exit code 1",
      "stderr_preview": "ModuleNotFoundError: No module named 'xxx'",
      "fail_count": 5,
      "first_fail_at": "2026-07-13T15:28:00",
      "last_fail_at": "2026-07-13T15:30:00"
    },
    "node_C": {
      "status": "pending"
    }
  }
}
```

### 3.3 BNOS 轮询

`CompositeNode` 管理器新增轻量轮询（每 3 秒读取 `status.json`），为后续 UI 展示提供数据。

### 3.4 连续失败告警

编排器新增逻辑：同一节点连续失败 ≥ 5 次 → `status.json` 中设置 `"alert": "consecutive_failure"`，BNOS 检测到后可弹窗通知。

## 四、实施顺序

| 阶段 | 内容 | 文件数 | 风险 |
|------|------|--------|------|
| **Phase 1** | 新增 `check_node_not_running()` 工具函数 | 1 | 低 |
| **Phase 2** | 重命名保护（3 个入口） | 3 | 低 |
| **Phase 3** | 批量永久删除保护 | 1 | 低 |
| **Phase 4** | 编排器写入 `status.json` | 1 | 中 |
| **Phase 5** | BNOS 轮询 + 健康状态读取 | 1 | 中 |
| **Phase 6** | 连续失败告警 | 1 | 中 |

## 五、不处理项

| 项 | 原因 |
|----|------|
| 清空画布时的进程停止 | 项目切换流程中已有节点停止逻辑，无需在 `clear_canvas` 中重复 |
| 展开面板删除按钮入口层保护 | 已被委托方 `remove_node_with_cleanup` 兜底 |
| `remove_node_from_canvas()` 原始方法 | 仅由内部代码调用，无用户直接触发路径 |
| F2 快捷键重命名 | 当前不存在 F2 绑定，无攻击面 |
