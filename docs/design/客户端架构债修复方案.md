# 客户端架构债修复方案

## 背景

三轮防呆修复后，代码库已从进程管理、文件持久化、信号生命周期等 8 个维度全面加固。但扫描发现三个系统性架构债，是后续 bug 的温床。

---

## P0-1：消除双重选择状态

### 现状

节点选中状态由两套独立系统同时维护：

| 系统 | 位置 | 操作方式 |
|------|------|----------|
| `box_selected_nodes` | `canvas_view.py` Python list | `append()`/`remove()`/`clear()` |
| `QGraphicsItem.isSelected()` | Qt C++ 内部 | `setSelected()`/`isSelected()`/`clearSelection()` |

两套系统在 5 个不同代码路径中手动同步：
- `canvas_selection.py` `on_node_selected()` / `_toggle_node_selection()`
- `canvas_box_select.py` `clear_box_selection()`
- `canvas_event_handlers.py` 框选处理
- `canvas_batch_ops.py` 批量操作
- `interaction_handler.py` Ctrl+单击

**后果**：Ctrl+单击的 double-toggle bug（已通过反转 setSelected 值修复，但治标不治本）。任何新功能的选中逻辑都必须两处同步更新。

### 修复方案

**不消除 `box_selected_nodes`**（40+ 处引用，改动风险太大），而是将其从"独立状态存储"变为 **"Qt 选择的投影"**：

1. `box_selected_nodes` 改为 **property**，每次访问时从 `QGraphicsScene.selectedItems()` 实时计算
2. 写入操作委托给 Qt 的 `scene.clearSelection()` + `item.setSelected()`
3. 删除所有手动 `setSelected()` + `box_selected_nodes` 同步代码
4. `_toggle_node_selection` 只用 `item.setSelected(!item.isSelected())`，不再维护 list

### 影响范围

| 文件 | 改动 |
|------|------|
| `canvas_view.py` | `box_selected_nodes` 从 list 改为 property |
| `canvas_selection.py` | 移除手动 list 操作，只调用 Qt API |
| `canvas_box_select.py` | `clear_box_selection` 简化为 `scene.clearSelection()` |
| `canvas_batch_ops.py` | 读取改为 `scene.selectedItems()` |
| `canvas_menus.py` | 读取改为 `scene.selectedItems()` |
| `canvas_event_handlers.py` | 框选只调 `setSelected()`，不再手动维护 list |
| `interaction_handler.py` | 仅调 `setSelected()` |
| `interaction.py` | `canvas.box_selected_nodes` → `scene.selectedItems()` |

## P1-1：修复懒导入引发的 UnboundLocalError

### 现状

`node_list_context.py` 和 `node_list_dock.py` 中 `CompositeNode` 在方法体内懒导入：
```python
def _decompress_composite_group(self, group_name):
    from ui.core.composite_node import CompositeNode  # ← 懒导入
    mgr = CompositeNode.get_instance()
    ...
```

如果 `CompositeNode` 的导入在条件分支内（如 `if not mgr:`），分支外的代码访问变量 → `UnboundLocalError`（已修复过一次）。

### 修复方案

将有 `CompositeNode` 懒导入的文件改用模块级 `try/except ImportError` 导入，函数内不再重新 import。

### 影响范围

| 文件 | 改动 |
|------|------|
| `node_list_context.py` | 函数内 `from ui.core.composite_node import` → 模块级 |
| `node_list_dock.py` | 函数内 `from ui.core.composite_node import` → 模块级 |
| `composite_node.py` | 移除 `_canvas_compress` 内的 `from ui.canvas.items.composite_node_item import` |
| `canvas_view.py` | `restore_composites` 内的 import 保持（可选导入，避免无复合节点时加载） |

## P1-2：消除 `__del__` 进程清理

### 现状

`terminal_process.py` 依赖 `__del__` 在 Python GC 回收时杀子进程：
```python
def __del__(self):
    try:
        self.stop()
    except RuntimeError:
        pass
```

已通过移除 QProcess parent 减少了警告，但 `__del__` 仍然**不可靠**（GC 时机不确定，Python 退出时不保证调用）。

### 修复方案

1. 在 `TerminalDock.closeEvent` / `stop_all_terminals` 中**显式调用** `terminal.close()`（已存在，需确认覆盖率）
2. `TerminalProcess.__del__` 改为**仅打 warning 日志**，不再尝试杀进程（杀进程应在上层显式完成）
3. `TerminalProcess` 新增 `dispose()` 方法作为显式清理入口

### 影响范围

| 文件 | 改动 |
|------|------|
| `terminal_process.py` | `__del__` 改为仅日志；新增 `dispose()` |
| `terminal_widget.py` | `close_terminal` 调用 `dispose()` 而非 `stop()` |
| `terminal_dock.py` | `closeEvent` 确认已调用 `stop_all_terminals` |
| `dock_manager.py` | `_stop_content_timers` 已覆盖 QProcess 发现 + 杀进程 |

## 实施顺序

```
P0-1（双重选择）→ P1-1（懒导入）→ P1-2（__del__）
```

P0-1 改动最大，先做。P1-1 和 P1-2 改动量小，放后面。
