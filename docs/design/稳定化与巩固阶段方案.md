## 三、第一阶段：功能冻结与路径重构

### 3.1 功能冻结

暂停以下工作：
- 多语言节点生成器（Rust/Node.js/Go/Java/C++/Ruby）
- 新功能特性开发
- 跨语言迁移（Python → Rust）

集中精力打磨已有功能，确保 Python 节点全流程稳定。

### 3.2 路径解析重构（P0）

**问题**：项目中有约 16 处使用 `os.path.abspath(__file__)` 推导项目根目录。在 PyInstaller onefile 模式下，`__file__` 指向临时解压目录 `_MEIxxxxxx`，导致：

- 配置文件写入临时目录，退出即丢失
- 日志文件无法持久化
- 画布布局保存失效

**方案**：创建 `ui/core/paths.py`，提供两个核心函数：

```python
# ui/core/paths.py（新建）

import os
import sys

def get_resource_path(relative_path: str) -> str:
    """
    获取资源文件路径（兼容开发模式和 PyInstaller 打包模式）
    
    读操作：读取打包内静态资源（图标、字体、模板等）
    """
    try:
        # PyInstaller onefile 模式：资源解压在临时目录
        base_path = sys._MEIPASS
    except AttributeError:
        # 开发模式：从 ui/core/paths.py 向上两级到项目根
        base_path = os.path.dirname(os.path.dirname(os.path.dirname(os.path.abspath(__file__))))
    return os.path.join(base_path, relative_path)


def get_user_data_dir(app_name: str = "BNOS") -> str:
    """
    获取用户数据目录（可写，用于配置和日志持久化）
    
    写操作：配置、日志、缓存等运行时产生的数据
    """
    if sys.platform == "win32":
        base = os.environ.get("APPDATA", os.path.expanduser("~"))
        return os.path.join(base, app_name)
    elif sys.platform == "darwin":
        return os.path.expanduser(f"~/Library/Application Support/{app_name}")
    else:
        return os.path.expanduser(f"~/.{app_name.lower()}")


def ensure_user_dir() -> str:
    """确保用户数据目录存在，返回路径"""
    path = get_user_data_dir()
    os.makedirs(path, exist_ok=True)
    return path
```

### 3.3 批量替换路径引用

需要修改的文件清单：

| 文件 | 当前方式 | 修改为 |
|------|---------|--------|
| `ui/core/app_config.py` | `__file__` 推导 + 写配置文件 | `get_user_data_dir()` 写配置，`get_resource_path()` 读默认值 |
| `ui/core/logger.py` | `__file__` 推导 logs 目录 | `get_user_data_dir()` + `logs/` 子目录 |
| `ui/core/canvas_layout.py` | `__file__` 推导路径 | 跟随项目目录，使用项目路径参数 |
| `ui/main_window/` 等 UI 模块 | `__file__` 读图标/字体 | `get_resource_path()` 读资源 |
| `ui/core/project_load_worker.py` | 工作目录推导 | 保持项目路径传参方式 |

### 3.4 配置持久化改造

```
用户数据目录结构 (AppData/Roaming/BNOS/)：

│   └── app_config.json          ← 用户偏好配置
```

### 5.3 打包模式选择

| 模式 | 优点 | 缺点 | 适用场景 |
|------|------|------|---------|
| **onefile** | 单文件分发，用户体验好 | 启动慢（需要解压），首次启动需解压 100MB+ PySide6 | 小项目、内部工具 |
| **onedir** | 启动快，增量更新方便 | 需要安装程序封装 | 大型项目、面向终端用户 |

**建议**：先使用 onefile 验证打包链路，后续切换到 onedir + Inno Setup 制作安装程序。

## 七、不应优先进行的工作

以下工作在稳定化阶段明确排除，待工程基础设施完善后再评估：

| 事项 | 排除原因 | 何时再评估 |

## 附录：回滚指南

每个阶段独立可回滚，如果某阶段出现问题：

1. **路径重构出现问题**：`paths.py` 模块独立，直接回退该文件并恢复 `__file__` 引用
2. **测试补全出现问题**：测试文件独立，不影响主程序运行
3. **打包配置出现问题**：spec 文件独立，不影响源代码
4. **性能基线出现问题**：纯只读采样，不影响程序行为
