# 复合节点多输入端口方案

## 概述

复合节点封装后，入口节点的所有 `input_ports`（`source=node`）暴露为复合节点的画布锚点，使外部节点可以分别连接到不同的输入端口。同时内部子节点支持同层级并行执行。

## 背景

### 封装前

```
┌─ preprocessor ─────────────┐
│ ● input (data)              │
│ ○ image                     │  ← 两个输入端口
│ ○ config                    │
│                     ■ output│
└─────────────────────────────┘
    ↖ 外部节点A  ↖ 外部节点B
```

### 封装前（旧行为）

```
┌── pipeline ────────────┐
│ ● data                 │  ← 只有 1 个输入，丢失了 image/config 端口
│              □ b_out   │
└────────────────────────┘
```

### 封装后（新行为）

```
┌── pipeline ────────────┐
│ ● data (主)             │
│ ○ image                 │  ← 保留入口节点的所有 source=node 端口
│ ○ config                │
│              □ b_out   │
└────────────────────────┘
```

## 技术方案

### 端口数据结构

`_identify_ports()` 新输出格式：

```json
{
  "input_ports": [
    {
      "internal_node": "preprocessor",
      "type": "input",
      "port_name": "data",
      "display_name": "数据输入",
      "entry_port": null
    },
    {
      "internal_node": "preprocessor",
      "type": "input",
      "port_name": "image",
      "display_name": "图像输入",
      "entry_port": "image"
    },
    {
      "internal_node": "preprocessor",
      "type": "input",
      "port_name": "config",
      "display_name": "配置输入",
      "entry_port": "config"
    }
  ],
  "output_ports": [
    {
      "internal_node": "processor_b",
      "type": "output",
      "port_name": "processor_b_out",
      "display_name": "processor_b"
    }
  ]
}
```

| 字段 | 说明 |
|------|------|
| `port_name` | 复合节点画布锚点名称 |
| `display_name` | 画布标签文本 |
| `entry_port` | 映射到入口节点的 `input_ports[].name`，`null` 表示主数据输入 |

### 锚点渲染层级

| 层级 | 锚点类型 | 尺寸 | 颜色 |
|:--:|------|:--:|------|
| 主输入 | `data` 端口 | 16px | 绿色 `#4fc34f` |
| 子输入 | `source=node` 端口 | 10px | 绿色 `#4fc34f` |
| 输出 | DAG 叶子节点 | 10px | 红色 `#f06060` |

### 数据流路由

```
外部节点A ─output.json──→ _port_routing.input["data"]   ──→ entry.process(inp["data"])
外部节点B ─output.json──→ _port_routing.input["image"]  ──→ entry.process(inp["data"]["image"])
外部节点C ─output.json──→ _port_routing.input["config"] ──→ entry.process(inp["data"]["config"])
```

`_port_routing` 数据结构：

```json
{
  "_port_routing": {
    "input": {
      "data": {"source_output_path": "nodes/ext_a/output.json"},
      "image": {"source_output_path": "nodes/ext_b/output.json"},
      "config": {"source_output_path": "nodes/ext_c/output.json"}
    },
    "output": {
      "processor_b_out": {
        "target_composite": null,
        "target_node": "consumer",
        "target_port": "default"
      }
    }
  }
}
```

### 封装/展开同步

**封装时**（`_sync_configs_for_collapse`）：

```
入口节点 config:
  listen_upper_file = "nodes/ext_a/output.json"   → _port_routing.input["data"]
  port_mappings.image = "nodes/ext_b/output.json"  → _port_routing.input["image"]
  port_mappings.config = "nodes/ext_c/output.json" → _port_routing.input["config"]
                ↓ 清除入口节点中的外部引用
  listen_upper_file = ""
  port_mappings = {}
```

**展开时**（`_sync_configs_for_expand`）：

```
_port_routing.input["data"]   → entry_config.listen_upper_file
_port_routing.input["image"]  → entry_config.port_mappings["image"]
_port_routing.input["config"] → entry_config.port_mappings["config"]
```

## 内部并行执行

### 拓扑层级分组

```
DAG: A → B, A → C, B → D, C → D

旧：_topo_sort() → ['A', 'B', 'C', 'D']  ← 串行
新：_topo_sort_levels() → [['A'], ['B', 'C'], ['D']]  ← B/C 并行
```

### 执行模式

```python
for level in self._topo_sort_levels():
    if len(level) == 1:
        self._process_node(level[0], ctx, external_input)  # 串行
    else:
        with ThreadPoolExecutor(max_workers=len(level)) as executor:
            futures = {executor.submit(self._process_node, n, ctx, ...): n for n in level}
            for future in as_completed(futures):
                future.result()  # 并行
```

### 线程安全分析

| 操作 | 安全性 |
|------|:--:|
| `_build_input` 读取 `ctx` | 安全 — 只读上游已完成层级 |
| `ctx[node_name] = out` | 安全 — 每个线程写不同 key |
| `_write_output` 写文件 | 安全 — 不同节点写不同路径 |
| `_try_read_cache` 读文件 | 安全 — 只读缓存文件 |
